# 타당성 평가서 — 무중 MVP

입력: 의도 정리서 `ideation/intent-capture/intent-statement.md`(문제 3가지, 보호자 중심 고객, 성공 기준 "11/5 전체 흐름 1회 완주", MVP 범위 확정), 타당성 질문 파일 `feasibility-questions.md`의 Q1~Q12 답변, 참고 문서(기술명세서 v0.2 §1·§8·§11·§13·§14).

## 결론

**조건부로 가능하다.** 서비스 경계와 기술 선택은 확정돼 있고(Q5), 비용은 교육 과정이 지원하며(Q7), 실제 아동 자료를 쓰지 않아(Q4) 규제 부담도 낮다. 다만 11/5까지 전체 흐름을 완주하는 성공 기준은 아래 세 가지 조건에 크게 기댄다.

1. **외부 AI 접근권이 10월 중순까지 확보돼야 한다.** 제브는 승인 대기(Q1), OpenAI 키는 미준비(Q2)다. 연습 흐름(J2~J5)과 자유대화의 실시간 음성이 둘 다 이 접근권에 묶여 있다.
2. **PoC가 10/13까지 끝나고, 미달이면 10/19~10/23 안에 대체 경로가 정해져야 한다(Q3·Q9).** 대체 경로(Realtime API 교체, 대체 판정)는 기술명세서 §14.3상 "요구사항 변경 후"에 검토하는 항목이라 범위 영향이 있다.
3. **실시간 음성·AI 연동 경험이 없는 팀(Q6)이 가장 어려운 부분을 일찍 익혀야 한다.** 첫 볼트에 PoC와 학습 시간을 넣고, 이 부분을 맡을 담당을 Unit 나누기 단계에서 정해야 한다.

## 기술 타당성

| 영역 | 판단 | 근거 |
|---|---|---|
| 서비스 경계 | 가능 — 결정 완료 | 보호자 서버·아동 서비스 두 개, 모델 셋, PostgreSQL·Neo4j 구조가 확정됐다(Q5, 기술명세서 §1.1·§1.2) |
| 보호자 앱·기록·리포트 | 가능 — 위험 낮음 | 팀이 익숙한 웹·서버 개발 영역이다. PDF·푸시는 확정 기술로 처리한다(Q5) |
| 실시간 음성(GPT-Live 중계) | 위험 높음 | 팀 경험 없음(Q6). 출력 게이트·발화 끝 판정·에코·재연결 맥락 복원이 PoC 대상이다(기술명세서 §14.3). 키 미준비(Q2) |
| 진행 중 판정(제브) | 위험 높음 | 승인 대기(Q1). 한국어 아동 발화 정확도·확신 문턱이 PoC 대상이다 |
| 분석 AI(활동 전·후) | 가능 — 위험 중간 | 텍스트 LLM 구조화 출력이라 실시간보다 쉽지만 팀 경험이 없다(Q6). 금지 표현 검사·재시도가 필요하다 |
| 시연 환경 | 가능 — 위험 중간 | 강의장 와이파이(Q10)에서의 실시간 음성 품질, 노트북(Q11) 스피커 에코, 강의장 접속용 HTTPS 방식 미정(기술명세서 §11.1) |

## 일정 타당성

| 기간 | 할 일 | 근거 |
|---|---|---|
| 10/8 ~ 10/13 | OpenAI 키 준비 → GPT-Live PoC. 제브 승인이 나면 제브 PoC를 바로 시작 | Q3, Q9 |
| 10/19 ~ 10/23 | PoC 미달 항목이 있으면 대체 경로를 팀 합의로 결정 | Q3, intent-capture Q7 |
| ~ 11/5 | 전체 흐름 구현·시험·시연 | intent-statement 성공 기준 |

4주 중 첫 1~2주가 외부 접근권과 PoC에 묶여 있다. 대체 경로를 10/23에 정하면 구현 기간이 약 2주로 줄어든다. 그래서 PoC를 기다리지 않아도 되는 부분(보호자 앱·계정·기기 등록·기록·리포트, 가짜 모델로 시험하는 아동 서비스 상태 기계)을 5명이 병렬로 먼저 진행할 수 있게 Unit을 나눠야 한다(intent-capture Q11).

## 비용 타당성

AWS와 AI API 비용은 교육 과정이 지원한다(Q7). 한도가 있지만 금액은 모른다(Q12). 실시간 음성 비용은 사용 시간만큼 늘어나므로, 한도를 확인하기 전까지는 실제 모델 호출을 PoC와 주요 시연 리허설로 제한하고 평소 시험은 가짜 모델로 하는 것이 안전하다.

## 규제·개인정보

실제 아동은 개발·시연에 참여하지 않는다(Q4). 그래서 실제 아동 개인정보 처리에 따르는 법적 의무(만 14세 미만 법정대리인 동의 등)를 시연 전에 운영 수준으로 갖출 필요는 없다. 다만 동의 4항목, 최소 정보 전송, 삭제 연쇄는 요구사항(FR-A03·A08, NFR-04)이므로 기능으로는 그대로 구현한다. 세부 판단은 제약 목록의 규제 항목에 적었다.

## 다음 단계로 넘기는 것

- 범위 정의: Should·Could 중 PoC 결과에 따라 연기할 후보를 정한다.
- Unit 나누기·납품 계획: PoC 담당과 첫 볼트, PoC를 기다리지 않는 병렬 작업을 배치한다.
- 요구사항 분석: 성공 기준의 "끊김 없이" 판정 기준과 수용 테스트의 관계를 확인한다(intent-capture 검토 의견 R-01·R-02).
