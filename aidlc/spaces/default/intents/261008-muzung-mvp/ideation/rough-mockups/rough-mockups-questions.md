화면 설계 v1.6에는 이미 화면 30장(보호자 화면 16, 팝업 9, 시트 2, 아이 기기 웹 2, PDF 템플릿 1)과 화면별 분기 표, 탭 규칙(04 홈·08 자유대화·18 연습·26 기록)이 확정돼 있습니다. 그래서 진입점·핵심 흐름·정보 구조는 다시 묻지 않고, 화면 설계에 없거나 이 단계 산출물의 방향을 정하는 것만 묻습니다. 각 `[Answer]:` 뒤에 고른 선택지 글자를 적고, 직접 쓰려면 `X` 뒤에 내용을 적습니다.

## Q1. 이 단계 산출물의 방식

화면 설계 v1.6이 이미 화면·분기를 정해 두었기 때문에, 새 와이어프레임을 그리면 같은 내용이 두 벌 생기고 서로 어긋날 위험이 있습니다. 이 단계 산출물을 어떻게 만들까요?

질문 중 확인(사용자 추가 질문 "Q1 : 해당 질문이 무슨 의미인가? 와이어프레임을 다시 만드는 이유는?"에 대한 답): 이 단계는 원래 화면 설계가 없는 프로젝트가 저충실도 와이어프레임을 처음 그리는 단계다. 무중은 화면 설계 v1.6이 확정돼 있어 다시 그릴 이유는 없지만, 이 단계는 이후 단계가 읽는 `wireframes.md`·`user-flow.md`를 남겨야 한다. Q1은 와이어프레임을 다시 만들자는 질문이 아니라, 다시 만들지 않고 v1.6을 참조하는 방식(A)으로 마쳐도 되는지 확인하는 질문이다.

A. 화면 설계 v1.6을 기준으로 삼아, 화면 목록·핵심 흐름도·화면별 접근성 메모만 정리한다(새 그림은 그리지 않고 화면 번호로 참조)
B. 화면 설계와 별개로 저충실도 와이어프레임(ASCII)을 새로 그린다
C. 핵심 동선 화면(04·08·12·17·18·27·28·29·D0·T19)만 ASCII로 간단히 그리고 나머지는 화면 번호로 참조한다
D. Not yet defined
X. Other (please specify)

[Answer]: A

## Q2. 시연에서 보호자 앱을 띄울 장치

A. 안드로이드 폰

D. Not yet defined
X. Other (please specify)

[Answer]: C

## Q3. 접근성 목표 수준

화면 설계와 요구사항에는 접근성 수준(WCAG 등)이 적혀 있지 않습니다. 아이 기기는 음성으로만 참여하고 화면은 캐릭터 표정·색만 보여 줍니다(FR-E16). 접근성은 어디까지 목표로 할까요?

질문 중 확인(사용자 추가 질문 "Q3 질문의 내용을 파악하지 못함"에 대한 답): 접근성은 시력이 약하거나 마우스를 쓰기 어려운 사람 등도 화면을 쓸 수 있게 만드는 정도이고, WCAG는 그 국제 기준이다. A는 보호자 앱에서 글자 대비·입력 라벨·키보드 조작·색만으로 상태를 알리지 않기를 지키고 아이 기기 캐릭터는 표정으로도 상태를 구분하는 수준(부담 작음), B는 따로 신경 쓰지 않음, C는 화면 읽기 프로그램 대응 등 WCAG 2.1 AA 전체(부담 큼)다. 시연 목적과 일정상 A를 권장했다.

A. 보호자 앱은 WCAG 2.1 AA의 기본(글자 대비, 입력 라벨, 키보드 조작, 색만으로 정보 전달하지 않기)을 지키고, 아이 기기 화면은 색 외에 표정으로도 상태를 구분한다
B. 시연 범위에서는 별도 접근성 목표를 두지 않는다
C. WCAG 2.1 AA 전체를 목표로 한다
D. Not yet defined
X. Other (please specify)

[Answer]: B
