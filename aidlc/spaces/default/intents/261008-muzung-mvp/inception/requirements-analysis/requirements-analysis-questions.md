# 요구사항 분석 질문 — 무중 MVP

이 파일은 요구사항 분석 단계에서 오간 질문과 답을 모두 기록합니다. 질문의 근거는 주 입력 문서 `02_요구사항_입출력명세_v1.4.md`(이하 요구사항 v1.4)의 카드별 '넘긴 결정·참고', 기술명세서 v0.2 §13(값 목록)·§14(미결), 기능명세서 v1.3 §9.2(미결)입니다.

이미 정해진 것은 다시 묻지 않습니다.
- 요구사항은 새로 만들지 않고 요구사항 v1.4의 카드 70건(Must 55 · Should 12 · Could 3)을 그대로 정리한다. FR·NFR·화면·DATA·EV·기능 ID·J1~J7을 추적 키로 그대로 쓴다(요청 진행 방식 1).
- 카드의 '완료 기준'은 수용 테스트 기준, '하지 않는 것'은 구현 금지 사항이다(요청 진행 방식 2).
- Must는 줄이지 않고, Should는 모두 넣은 뒤 10/23에 재검토하며, Could는 가장 낮은 순서로 둔다(intent-capture Q9, scope Q1·Q3).
- 성공은 11/5 전체 흐름 완주로 판단하고, 통과하지 못한 Must 완료 기준은 시연 뒤 보완 목록으로 넘긴다(scope Q4·Q5).
- 기술명세서에 확정(✅)으로 적힌 값(공백 4분+2분, 판정 입력은 GPT-Live 입력 전사만 등)은 다시 묻지 않는다(feasibility 교정).

이번 단계에서는 요구사항의 **동작**을 바꾸는 팀 결정 대기 항목(기술명세서 §14.1, 기능명세서 §9.2)과, 요구사항 문서에 목표값이 없는 비기능 항목만 묻습니다. 시간·횟수·형식 같은 **값**(기술명세서 §13의 ⬜·🧪 항목: 연결 판정 시간, 등록 코드 형식, 기기 토큰 만료, 연습 회차 상한 등)과 AI 동작 명세로 넘긴 항목(§14.2 G-03·G-06·G-08·G-09·G-16)은 해당 설계 단계(기능 설계·NFR·인프라 설계)에서 묻습니다.

각 `[Answer]:` 뒤에 고른 선택지 글자를 적고, 직접 쓰려면 `X` 뒤에 내용을 적습니다.
