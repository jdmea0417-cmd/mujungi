## 2. 참여자별 검토와 추론

### 리드(aidlc-pipeline-deploy-agent)

- 기술명세서 ✅ 항목과 타당성 Q5에서 팀이 확정한 🟡 항목(브랜치·커밋 형식, PR 리뷰 1명 + CI, Monorepo, 시험 도구, ESLint·Prettier, EC2 1대)을 팀 사실로 보고 다시 묻지 않았다.
- org 기본값(트렁크 기반·스쿼시 병합, 스테이징 자동 배포, test-after, 80% 커버리지)은 제안으로만 표시했다.
- 충돌로 표시한 것: 배포(org 자동 배포 vs 기술명세 수동 `deploy.sh`·스테이징 없음), 병합 방식(문서에 없음), Bolt 브랜치·커밋 이름과 Jira 형식의 관계, 트렁크 이름(`master` vs `main`).
- 기술명세서에서 ALWAYS 7건·NEVER 13건의 규칙 후보를 뽑았다.

### 품질(aidlc-quality-agent)

- 시험 수준 7개·도구·시나리오 필수 사례 10개, CI의 유료 AI 금지를 기술명세 §10에서 확인했다.
- 시험 작성 시점은 문서에 없어 test-after / 표 기반 규칙 먼저 / 수용 시나리오 먼저 / TDD 선택지를 제안했다.
- 커버리지는 하한뿐 아니라 측정 단위·제외 범위·PR 차단 여부까지 지금 정해야 한다고 보았다(하한은 나중에 낮출 수 없으므로).
- 가짜 모델 소유, 테스트 계획서 담당, 실제 AI 시험 시점, 불안정 시험·가짜 시계, 브라우저 끝-끝 시험을 미정으로 짚었다.

### 개발(aidlc-developer-agent)

- Code Style에 ArchUnit 구조 규칙(§2.5)과 `ProblemDetail` + `code` 오류 형식(§5.9)이 빠졌고, 이름 규칙에 Java가 빠졌다고 보았다.
- 규칙 후보에 `com.fasterxml.jackson.databind` 직접 사용 금지, `useEffect`+`fetch`+`setInterval` 조회 금지를 더하자고 했다.
- 저장소 루트(`muzung/` vs `finalproject_v1/`), `aidlc-docs/`·`docs/` 경로 불일치, 5인 병렬 개발의 공유 지점(계약·Flyway 번호·`content/`·`AGENTS.md`)을 짚었다.
- Java 포매터·린터 선택지(Spotless 등)와 Java 기본 패키지, Adapter/Client 접미사, JSON 필드 표기, 생성물 커밋 여부를 미정으로 남겼다.

### 보안(aidlc-devsecops-agent)

- 보안·개인정보 규칙 후보(키 환경 변수, 합성 데이터, 보호자 소유 확인, 키·실제 아동 자료 저장소 금지, 아동 발화 로그 금지, GPT-Live 최소 정보, CI 유료 API 금지)를 강한 규칙으로 유지하자고 했다.
- "API 키를 브라우저에 보내지 않는다"를 원문 그대로 두면 웹 푸시의 VAPID 공개 키·구글 클라이언트 ID와 모순된다고 보았다.
- CSRF 끄기 금지, `/internal/` 외부 노출 금지, 기기 토큰 해시 저장, 시연 서버 CORS 금지를 추가 후보로 냈다.
- 비밀 유출 방지 장치, 저장소 공개 여부, SAST·의존성 점검 선택지를 제안했다. 비공개 저장소에서는 브랜치 보호·비밀 스캔이 요금제에 따라 막힐 수 있다고 짚었다.

## 4. 인터뷰 중 확인한 내용

- **Q7** — 사용자가 질문을 이해하지 못했다고 해서, 커버리지의 뜻(시험이 실행한 코드 줄의 비율)과 선택지별 부담(A 서비스별·차단, B 합산·경고, C 80% 초과)을 설명한 뒤 다시 받았다.
- **Q8** — B를 고르면 AI·음성 파일 시험까지 자동으로 도는지 물었다. 어느 선택지든 실제 AI 호출과 실제 음성 시험은 CI에서 돌지 않고, 시나리오·장애 주입은 가짜 AI와 전사 글로 자동 실행된다고 설명했다.
- **Q9** — `main`과 `dev` 브랜치가 따로 있는지, `dev`를 두지 않은 이유가 무엇인지 두 번 물었다. 지금 방식에는 `dev`가 없고, 이는 기술명세 §1.2·ADR-001, 시연 서버 1대, PR 리뷰 + CI, 4주 일정에서 나온 것이며, 시연 전 고정은 `main` 태그로 할 수 있다고 설명했다.
- **Q10** — 자동 배포(Q9=B)로 정해져 질문이 필요 없어 보인다는 의견이 있었다. 배포 실행자·시점은 필요 없어졌고 확인·되돌리기만 남는다고 설명했고, 사용자가 지금 정하기를 골라 자동 배포 기준 선택지로 다시 물었다.
- **Q14** — 사용자가 질문을 이해하지 못했다고 해서, 강한 규칙(이후 모든 단계에서 어기면 결함, project.md)과 일반 관례(조정 가능, team.md)의 차이와 후보 23개의 번호별 목록(보안·개인정보 1~11, 기술 관례 12~23)을 설명한 뒤 다시 받았다.
- **Q15** — 인터뷰 도중 사용자 지시("현재 추가된 문서들 또한 참고하여 앞으로의 과정 진행. 앞선 결정과 충돌되거나 추가 확인이 필요한 경우, 해당 과정 다시 진행")가 추가되어 ADR_2S를 이전 결정과 대조하고 후속 질문을 만들었다.
- **Q16·Q17** — Q3(새 저장소)의 후속으로 AI-DLC 기록 위치와 옮기는 방법을 물었다.

## 6. ADR_2S 대조 결과(Q15)

- 사용자 지시로 ADR_2S(ADR 11개, 아키텍처 문서 8개, README, decision-log)를 이전 결정과 대조했고 충돌 21건(K-01~K-21)이 나왔다. 큰 충돌은 진행 중 판정 엔진(K-01), 출력 게이트 범위(K-02), PoC 날짜(K-03), 리포트 내용(K-04), 아이 삭제(K-05), 서버 간 통신·보호자 실시간 갱신(K-12), 장애 뒤 재개(K-13)다.
- Q15=A로 문서 순서를 화면 설계 → 요구사항 → 기능명세서 → ADR_2S → 기술명세서 → AI 동작 명세로 정했다. 화면·요구사항과 다른 ADR 내용은 따르지 않으며, 승인된 단계(의도 파악·타당성·범위 정의·대략 화면)는 다시 하지 않고 메모만 남긴다.
- 이 단계와 관련된 ADR 항목의 처리:
  - ADR-001(Git 기본: `main`, `feature/{JiraKey}`, 커밋 형식, PR 리뷰 1명 + CI, `AGENTS.md`)은 이번 결정과 일치한다. 병합 방식은 ADR에 없어 Q1=B와 충돌하지 않는다. 저장소 이름·위치(K-09)는 Q3·Q16·Q17로 정했다.
  - ADR-006(수동 `deploy.sh`, 자동 CD 미채택)과 달리 Q9=B로 자동 배포를 정했다. ADR_2S는 기술명세서보다 앞서지만, 이 단계에서 사람이 직접 정한 팀 결정이 둘 다보다 앞선다.
  - ADR-002(CI는 두 앱 build·test·lint·ArchUnit, 유료 AI 미호출)는 Q8·강한 규칙 8번과 일치한다.
  - ADR first-bolt(첫 볼트에 실제 GPT-Live·출력 게이트, K-18)와 달리 Q5=A로 가짜 AI 첫 조각을 정했다.
  - ADR의 원음 규칙(AI 출력 음성 비저장, 원음 바이트의 DB·로그·임시 디스크 우회 금지, DL-012-01/02)과 "다른 앱 Repository 직접 수정 금지"는 Q14 후보 11번·20번으로 올렸고, 11번은 강한 규칙, 20번은 일반 관례가 되었다.

## 8. 남은 불확실성과 이후 단계로 넘긴 항목

### 남은 불확실성

- **GitHub 비밀 스캔·푸시 보호**: 비공개 저장소에서는 요금제(GitHub Advanced Security 등)에 따라 켤 수 없을 수 있다. 켤 수 없을 때의 대안(예: gitleaks)은 정하지 않았고 CI 파이프라인 단계에서 다시 정한다.
- **브랜치 보호**: "PR 리뷰 1명 + CI 통과 뒤 병합"을 도구로 강제하는 브랜치 보호도 비공개 저장소에서는 조직 요금제에 따라 쓸 수 없을 수 있다. 쓸 수 없으면 팀 약속으로만 지켜진다. CI 파이프라인 단계에서 확인한다.
- **자동 배포의 비밀 정보**: 자동 배포(Q9=B)를 하려면 GitHub Actions가 시연 서버에 접근할 자격 정보를 가져야 한다. 공급자 AI 키는 CI에 두지 않는다(강한 규칙 8번). 배포 자격 정보의 보관과 범위는 배포 파이프라인·인프라 설계 단계에서 정한다.
- **원음 임시 파일**: 강한 규칙 11번(원음 바이트를 임시 파일에 두지 않음)은 기술명세 §5.4의 "outbox에 파일 경로로 등록하고 성공하면 임시 파일을 지운다"와 맞지 않는다. Q15 순서상 ADR_2S가 기술명세서보다 앞서고 강한 규칙이 확정되었으므로, 원음 전달 방식은 도메인 설계·계약 설계에서 이 규칙에 맞게 정해야 한다(K-06 연결).
- **AI-DLC 기록 경로**: Q17=B로 설정·기록을 그대로 옮기므로 새 저장소에서도 AI-DLC 기록은 프레임워크 경로 `aidlc/`에 남는다. 기술명세 §2.4의 `aidlc-docs/`·`docs/` 폴더를 따로 만들지는 정하지 않았다(Unit 나누기 또는 코드 생성 단계에서 확인).
- **첫 조각 확인 명령**: org 규칙은 확인 명령이 실제 끝-끝 결과를 보여야 한다고 한다. 가짜 AI 조각(Q5=A)으로 무엇을 보일지는 Construction 진입 때 사람이 고른다.
- **헬스 체크 세부**: 확인 대상(두 서버·웹 응답 등), 알림 경로, 이미지 태그 방식은 정하지 않았다.
