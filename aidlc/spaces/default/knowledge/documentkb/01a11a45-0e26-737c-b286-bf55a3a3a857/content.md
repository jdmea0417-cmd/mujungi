① 개정: A1.4에 따라 LLM MVP 개발 기본·Jev 비교 두 용도·게이트 검사 방식 선정과 통합 시험, 저장 사실/원문 기반 보고서·1:1:1 데모 관계를 연결했다.
② 대체: A1.1의 다섯 용도 Jev 우선/LLM 대안·사후 분류 확대와 판정 발췌 중심 리포트는 명시 이력으로 남기고 업무/Port 소유권·게이트·실패 구분은 보존했다.
③ 남은 TBD: 기본 LLM 기능/품질·두 용도 Jev POC/승인·게이트 방식/통합 검증·질문/임계값/물리 매핑·템플릿/PDF/화면 정합·1:1 제약 구현과 화면 충돌 7건.

# ADR-011 판정 엔진과 AI 역할 분리

- 상태: **Proposed / POC pending**. LLM 경로는 아래 범위의 **MVP 개발 기본값이며 기능·품질 시험이 필요**하다. Jev는 활동 중 반응 판정·출력 게이트 의미 검사 **두 용도만** 비교 후보이며 운영 사용은 해당 용도 POC 통과·승인 후다. 통과한 용도만 Accepted로 전환하고 다른 용도나 ADR 전체를 함께 승인하지 않는다.
- 기준: [AI 역할·MVP 범위·관계 보완 기준 A1.4](../ref/audit-addendum-ai-roles.md)가 해당 조항을 대체·구체화한다. 나머지는 [audit v1.1](../ref/mujung-architecture-update-audit-v1.1.md)과 9단계 업무·데이터·Port 소유권을 유지한다. A1.1을 적용한 10단계는 이전 개정 이력이며 A1.4가 현행 기준이다. 기준 작성일은 2026-10-08이다.
- 관련: [ADR-004 음성·게이트](ADR-004-communication-voice.md), [ADR-005 상태·시간](ADR-005-session-events-timeouts.md), [ADR-007 업무/Port 경계](ADR-007-module-boundaries.md), [결과 파이프라인](architecture/result-pipeline.md).
- 범위: 맥락·역할·계약·대안·결과·위험·시험과 남은 판단. 공급자 API/요금·확정 DTO/물리 컬럼·성능 수치를 새로 정의하지 않는다.

## 1. Context

9단계까지의 문서는 두 Spring 실행 앱, Realtime 음성 릴레이 B안과 출력 버퍼 게이트, 앱별 업무/데이터 소유권을 정리했다. 기존의 반응·후보 검토에는 판정 LLM 또는 별도 AI 의미 검토라는 표현이 있고, 리포트에는 LLM 설명을 사용하다 불일치하면 고정 템플릿으로 대체하는 경로가 있었다.

10단계 A1.1은 역할 분리와 Jev 우선 후보·다섯 용도 승인 계획을 제안했다. **A1.4는 기존 LLM을 MVP 개발 기본으로 두고 Jev 비교 범위를 반응 판정·출력 게이트 두 용도로 한정**한다. 기존 Text LLM의 생성·경험 구조화와 목표/상황 검토를 유지하며 Jev POC 완료를 기존 반응 판정 개발의 선행 조건으로 두지 않는다. 기본 경로 유지도 기능·품질 검증을 면제하지 않는다. 게이트는 검사 방식 선정과 음성 출력 경로 연동 검증이 별도로 필요하다.

공통 모델 호출 계약을 도입해도 업무 책임은 기존 앱/모듈에 남는다. 판정 입력을 구성하고 현재 상태·권한·단계·근거와 함께 결과를 사용하는 주체, 저장/전이의 소유자가 명확해야 한다. 정상적인 부정 판정과 호출 실패를 섞거나 의미 검사 한 번의 PASS를 음성 전달 전체 승인으로 취급하면 기존 상태/게이트 계약을 훼손한다.

## 2. Decision

### 2.1 역할 분업과 확정 범위

**GPT-Live는 대화, Text LLM은 생성과 MVP 기본 의미 판정, Jev는 핵심 두 용도의 판정 후보, Spring은 규칙, Java Template은 보고서**로 역할을 구분한다.

| 역할 | 담당 | 결정 상태 |
| --- | --- | --- |
| 아동과의 실시간 음성 대화·실시간 Cue 생성 | GPT-Live API(`gpt-live-1`) | 기존 확정 유지. 연결/이벤트는 ADR-004의 GPT-Live 계약 |
| 동적 목표·연습 상황·경험 구조화 등 생성 | Text LLM | 기존 생성 역할과 앱/업무 소유권 유지 |
| MVP 기본 의미 판정 | Text LLM의 `LlmJudgmentEngine` — §2.3의 기존 LLM 경로 | **MVP 개발 기본값·기능/품질 시험 필요**. 게이트 방식까지 자동 선정하지 않음 |
| 활동 중 반응 판정·출력 게이트 의미 검사 후보 | Jev(TypeSafe AI 판단 전용 모델) | **Proposed / POC pending, 두 용도만** |
| 상태·권한·동의·단계·횟수·Timeout 등 코드/데이터로 확정되는 규칙 | Spring 코드 | 확정 |
| 결과·리포트 조립과 PDF | Core 내부 Java Template/Report Renderer | 저장 사실 기반 기본 경로. 엔진/PDF 라이브러리·화면 최종안 정합 TBD |

Core API Spring과 Realtime Activity Spring의 두 실행 앱을 유지한다. Result Worker·Report Renderer는 Core 내부 기능이고 판정 Adapter는 호출 업무가 속한 앱 안에 둔다. 운영 코드에 Python 실행 앱, 별도 판단 서버 또는 세 번째 Spring을 추가하지 않는다.

Google·고정 ID 기기·즉시 ENDING A안·앱별 복구·HTTP 즉시 명령과 Outbox/Inbox 영속 전달·Broker 없음·PostgreSQL 물리 1개/앱별 스키마·기존 Flyway·Neo4j와 원음 비저장 원칙을 유지한다. 업무/쓰기/Port 소유권은 9단계 기준이며 관계 범위는 A1.4 §9와 이 문서 §2.11을 적용한다. LLM 기본 의미 판정과 요청별 2차 검토·리포트 서술 옵션을 구분하며 후자 둘은 **MVP 비활성**이다.

### 2.2 Spring과 의미 판정의 경계

**정답이 코드와 데이터로 확정되는 판단은 Spring이 수행하고, 자연어 의미 해석이 필요한 제한된 판정만 JudgmentEngine에 요청한다.**

| 판단 예 | 담당과 처리 |
| --- | --- |
| 활동이 ENDING인가, 현재 op인가, 동의가 유효한가 | 호출 업무의 Spring 코드가 현재 상태/권한/최신성을 검사 |
| 대응 전사가 누락됐는가, 처리 기한이 지났는가, 출력이 취소됐는가 | Spring 코드가 누락·기한·취소를 확인하고 진행/출력을 차단 |
| 아동이 상대의 중단 요청을 인정하고 반응을 바꿨는가 | Realtime `evaluation`이 제한된 기준·입력을 구성해 의미 판정 요청 |
| 출력에 금지 의미가 있거나 연습 전에 정답을 알려주는가 | Realtime 게이트의 판정 엔진+Spring 규칙. 검사 방식 선정·품질/출력 경로 시험과 나머지 전달 조건 필요 |

Jev를 비롯한 판정 엔진은 상태를 직접 바꾸지 않는다. 판정 결과는 호출 업무가 처리하는 입력이다. 호출 업무는 현재 단계·도움 여부·전사의 신뢰 가능 여부·사용한 기준 버전·현재 권한/작업을 함께 확인하여 기록·후속 동작·상태 전이를 결정한다. 공급자 SDK나 판정 구현체가 다른 업무의 Repository를 수정하지 않는다.

첫 반응·도움 후 반응·새 상황 반응은 기존 구분을 유지한다. 출력 생성/검사 결과와 아동 반응 판정, 미실시·미판정·활동 상태를 하나의 라벨이나 DB Enum으로 합치지 않는다.

### 2.3 용도별 책임과 승인 표

**Jev 비교 POC는 활동 중 반응 판정·출력 게이트 두 용도만 계획하며 둘 다 미실시·미승인이다.** 아래의 LLM 개발 기본값을 검증 완료 또는 자동 PASS로 읽지 않는다.

| 용도 | 앱·업무 소유자 | MVP 개발 기본 엔진 | 이번 Jev 비교 POC | Jev 상태/사용 승인 |
| --- | --- | --- | --- | --- |
| 활동 중 목표 행동/반응 판정 | Realtime `evaluation` — 첫/도움 후/새 상황 | 기존 LLM 경로. 개발을 Jev 비교 POC 완료에 종속시키지 않음 | 실시 대상·계획, 아직 미실시 | **Proposed / POC pending**. 통과·승인 후 해당 용도만 Accepted |
| 출력 게이트 의미 검사 | Realtime 게이트 | **검사 방식 선정 필요**. Jev·경량 LLM 등 후보 비교/출력 경로 확인 전 미승인 음성 미전달 | 실시 대상·모델 비교+출력 경로 연동 계획, 아직 미실시 | **적용 후보, Proposed / POC pending**. 반응 판정 합격을 승인으로 대신하지 않음 |
| 생성된 목표 후보의 조건 충족 검토 | Core `result` 후보 검사 경로 | 기존 LLM 경로 유지. 기능/품질 시험 필요 | 제외 | **MVP 미적용 / 후속 검토** |
| 생성된 연습 상황의 조건 충족 검토 | **Realtime `practice`** | 기존 LLM 경로 유지. 기능/품질 시험 필요 | 제외 | **MVP 미적용 / 후속 검토** |

Core의 기존 **사후 텍스트 AI·경험 구조화는 Text LLM 생성 역할**로 유지하고 Jev 대상으로 넣지 않는다. 기준본에 없던 별도 분류 기능을 추가하지 않는다. 이전 범위 확대는 §4의 이력으로 보존한다.

연습 상황 생성·검토는 Realtime `practice`, 목표 후보 생성/검사·체크포인트는 Core `result` 소유다. 기존 원격 등록과 쓰기 소유권, 목표 4요소·정의 버전·근거 조건, 형식/참조 검사와 실패/재시도 정책을 유지한다.

**비교 POC 제외는 기능·품질 검증 면제가 아니다.** 기존 LLM의 실제 모델·질문·출력 계약·구현 상태를 확인하고 대표·경계·불확실·실패 사례를 시험한다. 구현/검증되지 않은 부분을 검증된 경로로 표시하지 않는다. 실제 사용 엔진/질문/기준·시험 증거/승인은 기록하며 현재 합격 수치·실제 결과/승인 기록은 TBD다. 요청마다 Jev와 LLM을 연달아 호출하지 않는다.

### 2.4 판정 결과와 판정을 얻지 못한 상태

판정 질문별로 정해진 기준과 제한된 선택지만 사용하며 **선택지 순서를 고정**한다. 논리 예시 `OBSERVED / NOT_OBSERVED / UNCERTAIN`은 최종 라벨/선택지 확정이 아니다. **기존 `EvaluationLabel` 등 저장 표현의 이름은 바꾸지 않으며 논리 label/status와의 매핑은 TBD**다. 확신도 임계값은 POC의 사람 라벨 자료로 정하고 현재 TBD로 둔다.

**NOT_OBSERVED는 정상적인 판정 결과다.** 호출 실패·Timeout·근거 부족·저신뢰는 사용 가능한 판정을 얻지 못한 상태이며 NOT_OBSERVED 또는 아동 실패로 바꾸지 않는다. 논리 라벨 UNCERTAIN과 처리 상태 UNDECIDED의 역할·매핑도 실제 계약에서 구체화하며 라벨/상태를 같은 컬럼으로 단정하지 않는다.

| 용도 | 유효한 판정 | 저신뢰·근거 부족·호출 실패·Timeout |
| --- | --- | --- |
| 활동 중 목표 행동/반응 | 기준에 맞는 OBSERVED/NOT_OBSERVED 등 결과를 기록 | **미판정**과 사유를 구분해 기록. 판정 작업 실패만으로 세션을 종료하지 않음 |
| 출력 게이트 | 의미 PASS는 전달 조건 중 하나. 다른 조건까지 충족한 해당 음성만 전달하며 의미 FAIL은 폐기 | **미출력**. 기존 승인 안내·대체/회복 정책 적용 |
| 목표·상황 후보 | 조건 충족이면 다음 검증 단계, 부적합이면 후보 제외 | **후보 보류**. 검토를 얻지 못한 후보를 통과로 공개/등록하지 않음 |

활동 판정의 미판정 기록이 세션 비종료 원칙을 지키더라도 종료 요청·동의 철회·연결 장애 등 기존 활동 정책은 계속 적용한다. 판정 엔진이 장애 난 동안 모든 활동 진행을 무조건 허용한다는 뜻이 아니다. 미참여/미실시·기술적 미판정·정상 부정 판정은 각 사실로 유지한다.

### 2.5 출력 게이트의 다조건 전달과 차단 후 회복

**출력 게이트는 검사 방식 선정이 필요하다.** 기존 모델 TBD를 유지하고 Jev와 경량 LLM 등 후보를 비교한다. Jev는 두 용도 중 게이트의 **적용 후보, Proposed / POC pending**이며 별도 승인 전 운영 채택이 아니다. 의미 검사 품질과 음성 버퍼·전사 대응·승인 전달·취소·재생을 함께 확인한다. 미확인 AI 음성을 전달하지 않으며 어떤 구현을 선택해도 기존 릴레이 B안의 전달 조건을 유지한다.

1. Realtime이 출력 음성을 임시 메모리에 두고 앱 구간 분할·대응 전사를 확보한다. 분할 알고리즘·전체 완료 기준·매핑/버퍼 한도는 기존 TBD다.
2. 의미 검사뿐 아니라 **대응 음성·전사, 현재 활동 상태, 권한·동의, 작업 최신성, 취소 여부, 처리 기한**을 모두 검사한다.
3. 의미 PASS와 나머지 조건이 충족된 **해당 동일 음성**만 승인한다. 송신 직전에도 현재 상태/권한/최신성·취소/기한을 재확인한다.
4. FAIL·UNCERTAIN·저신뢰·근거 부족·호출 실패·Timeout·전사 누락/오대응은 미출력/폐기와 기존 대체 안내·회복으로 연결한다. 사용할 수 있는 검증된 검사 경로가 없다고 무검사 출력을 허용하지 않는다.
5. 검사 중 끼어들기·쉬기·종료·철회로 무효가 된 서버 버퍼/기기 대기열과 승인은 늦은 PASS로 다시 열지 않는다. 새 출력이나 재생성한 음성에 이전 PASS를 재사용하지 않는다.

기존 승인 안내와 새 AI 대체 음성을 구분한다. 안전 대체 응답은 기존 승인 안내·회복 정책을 따르며 **새 AI 음성은 다시 게이트 검사를 거친다**. 2차 검사 결과만으로 바로 출력하는 경로를 기본 계약으로 두지 않는다. 필수 조건을 확인하지 못하면 출력을 닫아 두는 **fail-closed** 원칙을 적용한다.

미출력 음성도 모델 맥락에는 남는다. 계속 대화가 허용된 회복에는 기존 앱 교정 지시와 새 출력 재검사를 연결한다. `session.instructions.append` 수락 ACK는 맥락 삭제·교정 완료·재생 승인이 아니다. 게이트 PASS·전달·기기 ACK·playbackMark 실제 재생 관측은 각각 다른 사실이다.

필요한 안전 검사를 생략하여 지연을 맞추지 않는다. 무거운 교육 판정·KG 조회를 동기 게이트에서 분리하는 것은 기존 **우리 설계 권고**로 유지하며 Jev 제안이 이를 구현/안전성 보장으로 바꾸지 않는다. 필수 근거가 없으면 전달을 보류한다.

### 2.6 앱별 JudgmentEngine Port와 구현체

판정은 **JudgmentEngine Port를 통해서만** 호출한다. 이는 모델 호출을 추상화하는 계약이며 별도 서버·공통 업무 상태 서비스가 아니다. 각 앱이 필요한 Port를 소유하고 호출 업무가 입력 구성·결과 사용/저장·상태 반영을 책임진다. 구체 Java 타입명·패키지·DTO는 TBD이며 여기의 이름은 논리 경계다.

| 구현체 | 역할·현재 적용 조건 |
| --- | --- |
| `LlmJudgmentEngine` | **MVP 개발 기본 엔진**(§2.3의 기존 LLM 경로), 기능·품질 시험 필요. 게이트 검사 방식은 선정 필요. 요청별 2차 검토 옵션과 별개 |
| `JevJudgmentEngine` | 반응 판정·게이트 **두 용도의 비교 후보**. POC 실험 호출은 허용하며 해당 용도 통과·승인 후에만 운영 사용 |
| `MockJudgmentEngine` | 개발 초기·첫 연결의 계약/실패 흐름 시험용. 실제 의미 품질·운영 승인 근거가 아님 |

공급자 SDK 타입은 Adapter 밖 도메인/공통 계약에 노출하지 않는다. Port 구현체를 바꾸어도 Realtime `evaluation`/게이트/`practice`, Core `result`/Worker의 소유권·공식 상태 변경 경로는 바뀌지 않는다. 서로 다른 앱이 같은 업무 서비스나 Repository를 공유하는 구조로 확장하지 않는다.

Jev·LLM 호출 키는 Realtime과 Core에 **각각 필요한 범위로만** 주입한다. 현재 Jev 비교 두 용도는 Realtime 소유이며 이 원칙을 Core의 새 Jev 업무 채택으로 해석하지 않는다. 기존 서버 키 보관·앱별 비밀/권한 분리 원칙을 따르며 브라우저에 키를 전달하지 않는다. 직접 API/게이트웨이 중 접근 경로·SDK/버전·요금제·실제 키 설정/회전은 TBD다.

### 2.8 대체 엔진과 요청별 2차 검토의 분리

현행은 §2.3의 **LLM 경로를 MVP 개발 기본**으로 사용하며 Jev는 반응 판정·게이트 두 용도의 비교 후 전환 후보다. Jev가 해당 기준을 충족하지 못하면 그 용도는 **비교 검증된 LLM 경로를 유지**한다. 게이트의 검사 방식 선정·통합 시험은 별도다. 기존 LLM도 검증이 없으면 완료로 표시하지 않고 미판정/후보 보류/미출력 계약을 적용한다. 모델·질문·기준·호출 경로가 바뀌면 영향 범위에 맞게 재검증한다.

개별 요청의 **LLM 2차 검토는 옵션, MVP 비활성**이다. UNCERTAIN 비율이 높으면 필요성을 검토하되 정확도 개선·추가 지연/비용·실패 처리를 확인하고 **별도 승인한 경우에만** 활성화한다. LLM을 주 엔진으로 사용하는 것, Jev 비교 또는 용도별 엔진 전환과는 별개다.

2차 검토가 승인되어 실제 요청된 경우만 ESCALATED의 논리 의미를 사용할 수 있다. 그 응답도 업무 조건과 현재성을 다시 확인하며 특히 게이트에서는 2차 PASS만으로 음성을 내보내지 않는다. 승인 절차/기준·계약·예산·실제 활성 조건은 TBD다. 이전 Jev 우선/LLM 대안 결정은 §4 이력으로 남긴다.

### 2.9 Text LLM 생성과 Core Java Template 보고서

Text LLM은 동적 목표·연습 상황·**Core의 사후 경험 구조화 등 생성**과 §2.3의 MVP 기본 의미 판정을 담당한다. 목표 후보 검토는 Core `result`, 연습 상황 검토는 Realtime `practice`의 기존 LLM 경로를 유지하며 필요한 형식/참조·의미 검토와 기능/품질 시험을 수행한다.

**Core 내부 Java Template + PDF가 결과·리포트의 기본 경로**다. Report Renderer는 Core 내부 기능으로 유지한다. 특정 판정 공급자에 의존하지 않는 **저장 사실 기반** 조립이며 템플릿 엔진/PDF 라이브러리와 구체 표시 항목은 TBD다. 구체 항목은 화면 설계 최종안과 정합해야 하며 A1.4가 참고한 현재 화면 설계 v1.5는 **아이 정보 + 기간 내 날짜별 대화 원문, AI 요약·평가 없음**이다. 이 참조를 상세 화면/데이터 계약 확정으로 확대하지 않는다.

대화 원문은 **저장된 전사와 근거 발화 ID**에 연결한다. LLM 요약·재작성 문장을 원문처럼 표시하지 않고 미판정·미실시를 정상 판정으로 채우지 않는다. 기존 판정 결과/엔진/버전은 처리 근거로 보존할 수 있으나 이를 보고서 필수 노출 항목이나 판정된 발화만의 발췌 조건으로 정하지 않는다. 실제 제공/반응·첫/도움 후/새 상황과 현재 자료 권한을 유지한다.

리포트 일부 서술 칸을 Text LLM으로 작성하는 것은 **옵션, MVP 비활성**이다. 나중에 별도 승인되더라도 저장 사실·판정·인용만 표현하고 근거 발화 ID를 연결한다. 근거 없는 새 평가·새 원인·새 수치를 생성하지 않는다. LLM MVP 기본 판정 선택이 이 서술 옵션을 켜지 않는다.

### 2.10 반응 판정 Timeout과 Cue 전체 예산

| 구분 | 기존 의미와 이번 적용 범위 |
| --- | --- |
| ADR-005 §10.1 반응 판정 | **5초 Timeout + Retry 1회**는 반응 판정 구현체 사이의 공통 **초기 제안값**이다. MVP 기본 LLM/해당 용도 승인 후 Jev 등 어떤 구현체를 쓰더라도 해당 반응 판정 용도로만 한정하며 실제 달성/적합성은 미측정 |
| ADR-005 §10.2 Cue | 최초 Cue 요청부터 실제 재생 시작까지 **전체 5초 초기 예산**. 구간 분할·전사 대응·검사·송신/재생 대기를 포함하며 재요청으로 최초 시각을 초기화하지 않음 |

§10.1의 Timeout/재시도 규칙을 출력 게이트나 Cue에 복사하지 않는다. 게이트의 처리 기한·실제 지연 기준은 별도 TBD/POC이며 Cue의 기존 조건부 추가 요청 정책은 그 전체 예산/조건을 따른다. 반응 판정 실패는 미판정 사유로 남기며 종료 요청·철회·연결 장애 등 기존 상태 정책과 구분한다.

### 2.11 보호자·아이·기기 관계의 연결

A1.4 §9의 MVP 관계는 **보호자 계정 1 : 아이 1 : 기기 1**이다. 기존 GuardianChild 등 보호자–아이 관계를 1:1로 제한하고 아이–기기도 1:1로 연결한다. UNIQUE 등 구현 방식은 TBD다. 아이 추가·삭제·선택과 공동 보호자 기능을 두지 않으며 아이 변경은 계정 삭제 후 새 가입으로 처리한다.

기기는 **고정 ID 사전 시드로 계정의 아이와 데모 연결**한다. 이는 운영 페어링·물리 소유권 인증이 아니다. 보호자 앱에는 아이/기기 선택 단계가 없고 상태 카드는 계정의 아이에 연결된 기기를 보여준다. 시작 대상은 계정의 아이→그 아이의 기기이며 Realtime의 허용·현재 연결·점유·원자 할당 검사를 유지한다. 미연결이면 “연결된 기기 없음”을 표시하고 시작하지 못하며 계정당 진행 세션은 1개다.

기록·리포트·목표는 아이 기준이며 activity_session은 child와 device를 함께 기록한다. 물리 필드를 새로 확정하지 않는다. 여러 아이·공동 보호자·형제 기기 공유는 후속이며 제약 확장 가능성을 남긴다. 관계의 실제 데이터/인가/시작/삭제 계약은 담당 문서에 연결한다.

### 2.12 화면 설계와의 미해결 충돌

다음은 A1.4 §12의 **팀 결정 대기 항목이며 이번에 채택하지 않는다.** 화면 설계의 제안과 현행 계약을 구분해 후속 연결만 남긴다.

| 미해결 화면 제안 | 이번에 유지하는 경계 |
| --- | --- |
| 원음 보관 동의를 필수로 받아 계정 삭제까지 보관 | 현행 원음 미저장 |
| 기기 웹의 서버 발급 코드→보호자 입력→기기 토큰 연결 | 현행 고정 ID 사전 시드·등록 UI 없음. 코드 등록은 미채택 |
| 기기 토큰을 브라우저 저장소에 보관 | 장기 기기 인증을 브라우저 저장소에 두는 것을 기본으로 쓰지 않음 |
| 보호자 실시간 전사 말풍선·Realtime API식 이벤트로 중계 | 경로 미정. 노출 시 게이트 통과 출력 범위와 GPT-Live 이벤트 계약 필요 |
| 판정 턴의 GPT-Live 자동 응답 보류 | 모델의 발화 시점 계약 유지. 게이트 출력 보류로 가능한지 반응 판정 POC 확인; 기능/API 확정 없음 |
| ENDED_UNCONFIRMED 표시를 새 상태로 적용 | 종료 미확인 표시/상태 충돌은 팀 결정 대기. 기존 상태/사유 분리를 유지하고 새 Enum을 확정하지 않음 |
| 세션·삭제 완료 푸시 알림 | 인프라 없음. MVP 포함 여부 미결정 |

## 3. Reason

- 코드로 정해지는 규칙과 제한된 자연어 의미 판정을 분리하여 모델이 상태·권한을 직접 결정하지 않게 한다.
- Text LLM의 생성/기본 판정 개발을 유지하고 Jev 비교는 두 핵심 용도의 증거로 전환 여부를 판단한다.
- 같은 Port의 구현체 교체와 업무 책임을 분리해 기존 두 앱/모듈·쓰기 소유권을 유지한다.
- 정상 부정 판정·미판정·미실시와 게이트 미출력을 구분해 근거 없는 아동 실패/출력 승인을 막는다.
- 보고서는 저장 사실·원문 근거로 조립하고 상세 표시 범위를 화면 최종안과 맞추며 서술 생성 의존을 기본에 두지 않는다.

이는 설계 선택 이유이며 Jev 품질 우월성·확신도 보정·비용 절감·전체 지연 달성 또는 템플릿/PDF 구현 성공의 시험 결과가 아니다.

## 4. Alternatives와 대체된 이전 선택

### 대체된 이전 선택. 반응 판정 LLM·일반 AI 의미 검토

10단계 A1.1은 기존 판정 LLM·일반 AI 의미 검토를 앱 소유 JudgmentEngine Port와 **Jev 우선 후보, 실패 시 비교 검증된 LLM 대안**으로 구체화했다. 반응·게이트·사후 화용 분류·목표 후보·상황 후보의 다섯 용도 Jev POC/승인 계획도 제안했다. 이는 **대체된 이전 선택**이다.

A1.4는 LLM을 MVP 개발 기본으로 두고 Jev 비교 POC를 반응·게이트 두 용도로 축소했다. 목표/상황 검토는 기존 LLM 경로, 경험 구조화는 기존 Text LLM 생성 역할을 유지한다. A1.1에서 확대했던 **사후 화용 분류는 기준본에 없던 기능이므로 현행에 추가하지 않는다**. 기존 Port·형식/근거 검사·정보 제한·미판정/상태 계약은 보존한다.

### 대체된 이전 선택. LLM 설명 우선, 불일치 시 고정 템플릿

초기 리포트의 LLM 설명 우선/불일치 시 고정 템플릿 대체는 A1.1에서 Core Java Template/PDF 기본으로 바뀌었다. 그때의 “DB 사실+저장 판정/엔진+서버 계산값” 구성과 “판정된 원문 발화 발췌”도 **A1.4에서 대체된 상세 전제**로 남긴다. 현행은 저장 사실 기반·전사/근거 발화 ID 연결이며 구체 표시 항목은 화면 최종안과 정합할 TBD다. LLM 일부 서술은 계속 옵션·MVP 비활성이다.

### Alternative A. 모든 용도에 Jev 즉시 적용 — 미채택

현재 Jev 비교는 반응 판정·출력 게이트 두 용도다. 목표/상황 후보로의 전환은 MVP 미적용·후속 검토이며 새 분류 업무를 추가하지 않는다. POC/승인 없이 운영에 적용하거나 한 용도의 합격을 다른 용도로 확대하지 않는다.

### Alternative B. 모든 판단을 Text LLM 또는 Jev에 위임 — 미채택

상태·권한·동의·단계·횟수·현재 작업/기한은 Spring 코드가 담당한다. 생성 업무와 제한된 의미 판정의 역할을 구분하며 모델 결과가 업무 상태를 직접 바꾸지 않는다.

### Alternative C. 요청마다 LLM 2차 검토 — 옵션, MVP 비활성

별도 승인 전 활성화하지 않는다. LLM MVP 기본 경로, Jev 비교와 용도별 전환 결정과 구분한다. 저신뢰 자동 ESCALATED, 2차 결과만의 게이트 출력은 기본 계약이 아니다.

### Alternative D. 별도 Python/판정 서버·공통 업무 서비스 — 미채택

각 앱이 필요한 Port/Adapter를 소유하고 기존 업무가 결과를 사용한다. Report Renderer도 Core 내부 기능으로 유지한다. 엔진 역할 분업을 새 실행 앱이나 Realtime `practice` 업무의 Core 이전으로 확대하지 않는다.

## 5. Consequences

### 장점

- 앱/업무 소유권을 유지하면서 판정 구현체를 용도별로 비교·선택할 수 있다.
- 호출 실패와 정상 부정 판정을 구분하고 출력 게이트의 나머지 필수 조건을 보존한다.
- 저장된 결과·사용 엔진/질문 버전·근거로 판정 사용을, 전사/발화 ID로 보고서 원문을 추적할 수 있다.
- 개발 초기 Mock으로 연결·실패 경로를 확인하고 실제 의미 품질 POC와 분리할 수 있다.

### 단점

- 용도별 라벨 자료·질문/선택지·합격 기준과 비교 실험이 필요하다.
- 후보 엔진의 호출·정규화·실패/확신도 처리와 키/설정 범위를 각 앱에서 구현해야 한다.
- 적용 후보인 게이트는 자체 지연·과다 차단·부적절 통과를 따로 검증해야 한다.
- 템플릿/원문 연결·화면 최종안 표시 범위/PDF 검증과 판정 엔진/버전 참조·운영 계약이 남는다.

## 7. First Bolt·용도별 POC와 후속 검증

현재 아래 시험은 **계획이며 미실시**다. 개발 초기에는 MockJudgmentEngine과 합성·성인 역할극 자료로 연결/실패 흐름을 확인할 수 있다. Mock을 의미 품질·실제 게이트 시험 완료로 기록하지 않는다. 실제 AI 출력 통합 시연을 “게이트가 작동하는 시연”으로 제시하려면 **검사 방식과 출력 차단 경로를 먼저 확인**해야 한다. 실제 아동 대상 사용 승인은 별도로 판단한다. POC pending인 Jev도 **POC 실험 호출은 허용**하며 운영 승인과 구분한다.

### 7.1 용도별 비교 계획

목표는 **10/17 전 두 용도의 1차 결과 확보**이며 달성/실측 결과가 아니다. 모델 호출·샘플 실행·측정 도구는 공유할 수 있지만 질문·정답 라벨·오류 지표·승인 기준은 분리한다.

| 용도/시험 | 1차 탐색 범위 | 확인할 항목 | 현재 상태 |
| --- | --- | --- | --- |
| 활동 중 반응 판정 | 아동 발화 샘플 **약 30~50개 + 사람 라벨** | Jev vs 현재 LLM 정확도·확신도별 정확도·지연·비용·미판정 사유, 첫/도움 후/새 상황 | 계획·미실시, 합격 수치 TBD |
| 출력 게이트 — 모델 비교 | 출력 샘플 **약 20~30개**. 정상·명백한 금지·맥락에 따라 달라지는 경계 사례 | 부적절 출력 통과·정상 출력 과다 차단·UNCERTAIN/Timeout 보류 구분 | 계획·미실시, 방식/합격 기준 TBD |
| 출력 게이트 — 출력 경로 연동 | 실제 음성 버퍼·전사·검사/승인·송신·기기 관측 경로 | PASS→검사한 그 음성만 전달, 전사 누락/대응 불확실→미전달, FAIL/Timeout→미전달+회복, 검사 중 끼어들기/종료→버퍼/대기열 취소, 취소 후 늦은 PASS→재전달 없음, 송신/실제 재생 구분 | 별도 계획·미실시. 텍스트 모델 비교로 대체하지 않음 |

샘플 수는 **1차 탐색 범위**이며 서비스 전체 판정 품질이나 출력 안전성의 검증 근거가 아니다. 자료 확보/사용에는 기존 동의·보존 계약을 적용한다. 소요 기간은 API 접근·입출력 계약·라벨 준비·게이트 구현 상태를 보고 산정하며 현재 TBD다. 정확도/확신도/지연/비용 합격값을 만들지 않는다.

Jev가 해당 기준을 충족하지 못하면 그 용도는 **비교 검증된 LLM 경로를 유지**한다. 확인된 경로가 없으면 미판정/후보 보류/미출력 계약을 지킨다. 반응 판정의 기존 LLM 개발은 Jev 비교 POC 완료를 기다리지 않으며, 비교 대상에서 제외한 목표/상황 LLM도 기능·품질 시험을 수행한다.

### 7.2 계약·실패·보고서 시험

- [ ] 각 앱 소유 Port·기본 LLM/Jev 후보/Mock의 역할과 필요한 키 범위·SDK Adapter 격리를 확인한다. 기본 LLM의 실제 모델/질문/출력 계약·구현 상태를 기록한다.
- [ ] 대표·경계·불확실·실패 사례를 통해 반응·목표/상황 검토의 결과/보류를 확인한다. 목표 후보 Core `result`, 연습 상황 Realtime `practice`, 경험 구조화 Text LLM의 기존 업무 소유권을 유지한다.
- [ ] 질문별 선택지 순서와 질문/입력/목표/기준 버전·엔진을 추적한다. 기존 EvaluationLabel 이름을 유지하고 label/status 매핑은 미정으로 구분한다.
- [ ] 정상 NOT_OBSERVED와 저신뢰·근거 부족·호출 실패·Timeout을 다르게 기록한다. 판정 실패만으로 세션 종료하지 않고 기존 종료·철회·연결 장애 정책은 적용한다.
- [ ] CONFIRMED의 업무 사용 결정, UNDECIDED의 사유와 실제 2차 요청이 없는 ESCALATED 금지를 확인한다. 기본 LLM을 쓴다는 이유로 2차 검토·리포트 서술 옵션이 켜지지 않는지 검증한다.
- [ ] 게이트 의미 PASS와 음성/전사 대응·상태·권한/동의·작업·취소·기한을 모두 확인한다. FAIL/UNCERTAIN/Timeout/전사 누락·오대응·미확인 검사 경로에서 미전달 처리한다.
- [ ] 검사 중 끼어들기·쉬기·종료·철회 뒤 늦은 PASS, 버퍼/기기 대기열 취소와 새 AI 대체 음성 재검사·교정 ACK/재생 승인 차이를 시험한다.
- [ ] 반응 판정 5초+Retry 1회 초기 제안과 Cue 최초 요청→실제 재생 전체 5초 예산을 각각 관측한다. Cue는 구간/전사 대기·검사·전달/기기 시작을 포함하고 재생성/재요청으로 최초 시각을 초기화하지 않는다.
- [ ] Java Template/PDF의 저장 사실 기반·화면 최종안 표시 항목과 전사/발화 ID 연결을 검증한다. LLM 요약을 원문으로 표시하거나 미판정/미실시를 정상 판정으로 채우지 않는다.
- [ ] 보호자 계정1:아이1:기기1·선택 UI 없음·계정당 진행 세션1개·미연결 시작 차단과 고정 ID 데모 연결을 관계/인가/시작 계약에 연결한다. 화면 충돌 일곱 항목을 자동 채택하지 않는다.

실제 결과에는 엔진/질문/기준·자료/사람 라벨·재현 조건·실패 사유·관측 지연/비용과 용도별 승인 근거를 연결한다. 모델·질문·기준·호출 경로 변경 시 영향 범위에 맞게 재검증한다. 문서 개정·Mock 연결·탐색 샘플 수를 구현/품질 승인으로 표시하지 않는다.
