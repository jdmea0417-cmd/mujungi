변환 방법:

- 기능명세서·기술명세서·AI 동작 명세는 원본 내용을 바꾸지 않고 Markdown으로만 옮겼다. 한글 글자 수가 원본과 같다.
- 요구사항 정의서는 행을 요구사항 카드로 바꿨다. 상세 설명은 원문 그대로 두고, 비고를 'ADR로 넘긴 값·결정 필요·검증 과제·화면 설계 참고·참고'로 나눴다. 기능명세서 §10.1 추적표로 기능 ID를 붙였다.
- 화면 설계는 HTML 안의 화면 데이터(상태·구역별 상태·분기)와 시안 글자를 화면 카드로 옮겼다. 본문의 버전 표시는 빼고, 버전별 변경 내용은 마지막 '변경 이력'에 모았다.

## 2. 읽는 순서와 우선순위

```
화면 설계 → 요구사항 정의서 → 기능명세서 → 기술명세서 → AI 동작 명세
```

문서끼리 다르면 **앞의 문서를 따른다**. 다섯 문서가 모두 같은 규칙을 적고 있다.

## 4. 문서 사이에서 다르게 적힌 곳 — 적용 기준

화면 설계 v1.5 최신본은 다른 문서보다 늦게 고쳐졌다. 아래 항목은 2장의 규칙에 따라 **화면 설계를 적용**한다. 뒤 문서의 해당 내용은 아직 화면 설계에 맞게 고쳐지지 않은 것이다.

| 주제 | 적용 (화면 설계) | 뒤 문서에 남은 내용 |

| 계정·아이·기기 | 보호자 계정 1 = 아이 1 = 기기 1. 아이 선택·추가·삭제 없음. 아이를 바꾸려면 계정 삭제(P7) 뒤 새로 | 요구사항 FR-A12 아동 삭제, 기능명세 CHILD-P4-001·P4 팝업 |
| 동의 | 4항목 모두 필수. 동의를 바꾸거나 철회하는 화면 없음(철회하려면 계정 삭제). 약관 개정 시 02에서 재동의 | 요구사항 FR-A08 동의 철회·기록 삭제, 기능명세 CONS-S02-002·003, 기술명세 동의 철회 전이 |
| 진행·끝 화면 | 자유대화·연습 모두 12 활동 진행, 17 활동 끝을 함께 쓴다(머리에 종류 표시) | 21 연습 진행, 23 연습 끝 |
| 상담용 리포트 | AI 요약·평가 없이 아이 이름·연령·관심사 + 기간별 대화 원문(날짜순)을 묶은 PDF. 28 범위 → 만드는 중 → 30 확인·저장·공유. 29 없음 | 요구사항 FR-D05·D06, 기능명세 RPT-S29-001·002, 기술명세 report 10개 항목 |

## 5. AI-DLC에 넣는 방법

| 위치 | 파일 |
|---|---|
| 주 입력(document input) | `02_요구사항_입출력명세_v1.4.md` |
| 참고 문서(`aidlc/spaces/default/knowledge/documents/`) | `00_문서_안내.md`, `01_화면설계_v1.5.md`, `03_기능명세서_v1.3.md`, `04_기술명세서_v0.2.md`, `05_AI동작명세_v0.1.md` |

```bash
SRC="<내려받은 폴더 경로>"
DST=~/finalproject_v1
KN="$DST/aidlc/spaces/default/knowledge/documents"
mkdir -p "$DST/docs" "$KN"
rm -f "$KN"/*.md                                   # 이전 입력 문서 정리
cp "$SRC/02_요구사항_입출력명세_v1.4.md" "$DST/docs/"
cp "$SRC"/{00_문서_안내.md,01_화면설계_v1.5.md,03_기능명세서_v1.3.md,04_기술명세서_v0.2.md,05_AI동작명세_v0.1.md} "$KN/"
find "$DST" -name "*:Zone.Identifier" -print -delete
```
