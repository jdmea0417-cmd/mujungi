## 0. 읽는 법

### 0.1 원칙

1. **요구사항 v1.4를 따른다.** 요구사항에 정의가 없거나 팀 판단이 필요한 항목은 팀 결정 문서(TD)로 다루고, 결정 전에는 본문에 적은 현재 기준을 따른다.

2. **요구사항에 없는 세부 동작 규칙도 본문에서 정한다.** 로그아웃해도 활동 계속, 철회 후 열람·삭제만 허용, 시작 수락 후 준비 취소와 참여가 겹칠 때 먼저 도착한 쪽 기준 등이다.

3. **값을 지어내지 않는다.** 요구사항이 ADR로 넘긴 시간·횟수·문턱값은 §8에 모았다. 잠정값(10초·30초·5초 등)과 예시값(전사 1.5초, 제브 800ms)은 ADR 후보로만 적는다. 목표당 시간 10분과 응답 공백 허용 시간 10초는 팀이 정한 임시값이다(ADR에서 바꿀 수 있음).

4. **화면 번호는 화면 설계 v1.5(2026-10-08)·요구사항 v1.4 화면 탭과 같다.** 02-1(약관 자세히 보기 시트)·P4(아이 삭제 팝업)를 포함해 25개다. PDF 저장 확인은 29의 저장 확인 시트로 둔다. 아동 쉬기 화면과 쉬기 기능은 두지 않는다(휴식 요청은 기록만 한다, CR-GAP). 아이 기기 화면은 D0(처음 켜기)·T19(상태 화면)로 쓴다.

5. **화면 표시는 화면 설계(시안)를 따른다.** 단 안전과 정확한 상태 전달에 반드시 필요한 다음 규칙은 시안에 없어도 둔다: P1의 '전송하지 못함'·'종료 확인 안 됨'과 참여 전 준비 취소(→ 04), 04·05의 부모 앱 조회 불가 표시, 첫 반응 전 정답·시범 금지, 29의 '진단 결과 아님' 안내, T19의 켜기/끄기.

6. **모델 세 가지의 역할을 나눈다.** 실시간 음성 대화는 GPT Live, 진행 중 반응 판정은 판정 모델 제브(Jev), 활동 전·후의 생성·분석은 분석 AI가 맡는다. 대화 역할(GPT Live)에는 판정 기준과 판정 결과를 주지 않고 '다음 행동 지시'만 준다(FR-F15).

7. **연습은 2안 「상황 반응 조절형」이다.** 목표마다 장면 대화를 하고 아이 반응에 따라 되묻기·집중 연습·변형 장면을 고른다(CR-PRACTICE). 연습 기록은 목표별 '장면 결과'와 '제공한 도움'으로 남긴다.

### 1.2 연결 3종

| 연결 | 구간 | 장애 판정 주체 | 장애 시 |
|---|---|---|---|
| 기기 연결 | 아동 기기 ↔ 아동 서비스 (음성·상태·명령을 하나의 연결로) | 아동 서비스 | 기술적 일시 정지 → 복구 대기 → 실패 시 기술 종료 (VOICE-ERR-001) |
| 음성 모델 연결 | 아동 서비스 ↔ GPT Live (서버 간) | 아동 서비스 | 위와 같음 |
| 부모 앱 연결 | 부모 앱 ↔ 보호자 서버 | — | 활동은 계속. 앱에 "실시간 상태를 불러오지 못하고 있어요"와 마지막 확인 시각·상태 |

- 기기 연결과 음성 모델 연결을 합쳐 **음성 대화 연결**이라 하고, 둘 중 하나의 장애를 **음성 대화 장애**라 한다. 12·21의 대화 흐름에는 대상 구분 없이 **'잠깐 끊김'**(시각 구간)으로 표시하고, 대상은 04·05의 기기 상태에서 구분한다.

- 보호자 서버가 아동 서비스의 상태를 받지 못하는 것은 연결 장애가 아니라 **기기 상태 확인 불가**다(내부 상태명). 04·05에는 '응답 없음'(회색)으로 표시한다.

- 아동 서비스 ↔ 제브, 보호자 서버 ↔ 분석 AI 호출은 연결 3종에 넣지 않는다. 제브가 제한 시간 안에 응답하지 않으면 판정 보류로 처리하고(CR-JUDGE) 음성 대화 장애로 보지 않는다.

- '관리 연결만 장애'인 상태는 없다.

### 1.3 기기 등록·기기 토큰

아동 기기는 처음 켜면 고정 등록 코드를 보여준다(D0). 보호자가 우리 집 기기(05)의 「+ 기기 등록」(05a)에서 그 코드를 넣으면 기기가 보호자 계정에 등록되고 **기기 토큰**을 받는다. 이후 기기는 코드 없이 기기 토큰으로 아동 서비스에 자동 연결하고, 보호자 서버가 그 기기에 배정한 활동에만 참여한다. 계정마다 아이 기기는 한 대이며 그 계정의 아이가 쓴다. 활동의 대상 아동은 그 계정의 아동이다. 기기의 저장 정보가 지워지거나 다른 기기를 쓰면 다시 등록하며, 새 기기를 등록하면 이전 기기 등록과 기기 토큰은 무효가 된다. 등록되지 않았거나 토큰이 유효하지 않은 기기는 거부한다. 기기 자동 검색·근거리 페어링은 두지 않는다. 코드 형식, 기기 토큰 만료·재발급, 등록 해제는 ADR이다. 브라우저의 마이크·소리 재생 허용을 위해 아동 기기에 「켜기」(= 기기 연결 시작)와 「끄기」(= 기기 연결 끊김)를 둔다(DEV-DISPLAY-001). 계정을 삭제하면 그 계정의 기기 등록과 기기 토큰은 무효가 된다(HOME-SET00-002).

### 1.4 진행 중 판정 흐름

별도 STT는 두지 않는다. 판정 입력은 GPT Live의 입력 전사만 쓴다.

일반 턴: 아이 음성 → 아동 서비스 → GPT Live → 자동 응답 → 아동 서비스 → 아이 기기 재생

판정 턴: 아이 음성 → 아동 서비스 → GPT Live (아동 서비스가 자동 응답을 보류)

(기회 문장 → GPT Live 입력 전사(텍스트) 수신 \[제한 시간 안에 안 오면 판독 불가\]

직후 등) → 아동 서비스가 제브 호출: 판정 질문·선택지·목표 판정 기준·장면·최근 몇 턴·전사

→ 선택지 + 확률 \[제한 시간 초과·확신 문턱 미달이면 판정 보류\]

→ 상태 기계가 다음 행동 결정 (이어 가기·되묻기·집중 연습·상황 다시 설명·확인·종료 …)

→ GPT Live에 '다음 행동 지시' 주입 + 응답 요청 (판정 라벨·확률·기준은 주지 않음)

→ 응답 재생

활동 뒤: 전체 전사 + 진행용 판정 기록 → 분석 AI 기록용 재판정 → 27 기록 확정

- 판정 지점은 J1(시작 안내 응답)~J7(생성 대본 사전 점검)이다. 선택지·확신 문턱·시간 제한·대체 경로는 CR-JUDGE(§4.9), 기능은 SYS-JUDGE-001~004(§5.9).

- 진행 중 판정(선택지·확률)은 진행용이다. 27의 기록은 활동 뒤 분석 AI가 전체 전사로 다시 판정해 확정한다(기록용 재판정, SYS-EVAL-001).

- 판정 턴 동안 아이 기기 T19는 '생각 중'을 보여준다. 응답 공백 허용 시간(아이 말이 끝난 뒤 무중이 응답하기까지 허용하는 최대 공백)은 10초(임시값, ADR에서 바꿀 수 있음)다. 10초 안에 응답이 준비되지 않으면(예: 전사나 제브 판정이 늦음) 판정 보류로 처리하고 무난한 되묻기나 맞장구로 응답한다(SYS-JUDGE-003). 예상 공백 1.1~2.5초는 추정치이며, 공백이 2초를 넘을 때 맞장구 문구를 낼지는 ADR이다.

### 1.5 기술 스택 문서와의 관계

ADR-002 v12는 단일 Spring 서버를 전제로 한다. 요구사항 v1.4는 아동 서비스와 보호자 서버를 나눈 2-Spring 구조이므로 ADR-002의 백엔드·통신·인증 절은 갱신이 필요하다. 다음도 ADR에 기록해야 한다: 모델 세 가지의 역할과 호출 위치(GPT Live·제브·분석 AI), 제브의 시간 제한과 대체 경로(응답 공백 허용 시간 10초(임시) 안), 제브 한국어 아동 발화 정확도·확신 문턱값 PoC 계획과 결과(검증 과제), 판정 턴 맞장구 문구, 아이 기기 에코 제거, 실시간 전사 중계 방식, 별도 STT 없음(판정 입력은 GPT Live 입력 전사만), 목표당 시간 10분(임시), 응답 공백 허용 시간 10초(임시). 이 문서는 구조의 책임 경계만 쓰고 프로토콜·스택 세부는 ADR을 따른다.

## 4. 공통 기능 정책

### 4.1 CR-STATE — 서로 다른 상태 축

| 축 | 값 | 관리 주체 |
|---|---|---|
| 활동 상태 | 시작 전 준비 / 시작 요청됨 / 기기 실행 확인 중 / 안내·참여 확인(preparing) / 진행(active) / 기술적 일시 정지 / 종료 요청됨 / 종료 처리 중(ending, 화면 표기 '끝내는 중') / 종료 확인됨 | 진행 중에는 아동 서비스, 저장은 보호자 서버 |
| 연습 진행 | 현재 목표(세션 계획 순서) + 장면(기본·변형, 장면 번호) + 대화 역할(친구·코치) + 판정 상태(일반 턴 / 판정 턴 / 판정 보류), 마지막에 마무리 | 아동 서비스 |
| 결과 상태 | 준비 중 / 전체 결과 / 부분 결과 / 자료 부족·결과 없음 / 생성 실패 | 보호자 서버 |
| 연결 관측 | 기기 연결·음성 모델 연결·부모 앱 연결별 정상·장애, 기기 상태 확인 불가(화면 표기 '응답 없음'), 대상별 마지막 확인 시각 | 기기·음성 모델: 아동 서비스 / 상태 미수신: 보호자 서버 / 앱 조회 불가: 부모 앱 |
| 종료 사유 | 정상 마무리 / 시작 전 아동 미참여 / 아동 중단 / 보호자 중단 / 기술 문제 / **대화 거부(휴식 요청 없이 공백 지속) / 비정상 오디오 공백 지속(휴식 요청 뒤 공백 지속) / 동의 철회(진행 중 보호자가 동의를 거둠)** | 아동 서비스가 확정, 보호자 서버가 저장. 보호자에게는 27에서만 보여주고, 정상 마무리가 아니면 26의 활동 줄에 '중간에 끊김'을 붙인다 |
| 부족·미실시 사유 | 관련 경험 미확인 / 판독 불가 / 판정 보류 / 해당 장면 미실시 / 시간 종료 등 | 보호자 서버 |

- 한 축으로 다른 축을 추정하지 않는다. 예: 아동 중단 + 부분 결과 + 관련 경험 미확인.

- **종료 요청과 종료 확인은 다르다.** 종료 확인은 아동 서비스가 해당 활동의 출력 중지와 음성 모델 세션 종료를 확인한 것이다. 기기 연결이 끊긴 상태에서도 확정할 수 있다.

- 서버 요청 접수, 시간 경과, 기록 수신 중단만으로 종료를 확정하지 않는다.

- 늦게 도착한 진행 이벤트·중복 요청·복구 이벤트·지연된 판정 결과가 종료 상태를 되돌리지 않는다.

- 목표 담기·선택은 활동 상태가 아니다. 진행 중 판정 결과(선택지·확률)는 연습 진행을 정하는 데만 쓰고 결과 상태가 아니다.

- 시작 전 아동 미참여는 종료 사유로 판정하지만 기록으로 저장하지 않는다(P3, CR-DATA).

### 4.2 CR-START — 활동 시작 조건 (공통규칙 '활동 시작 조건')

시작 요청은 다음을 모두 만족할 때만 받는다.

1. 기기 연결 준비 확인 (보호자 계정에 등록된 기기가 기기 토큰으로 아동 서비스에 연결됨, FR-A06·A11)

2. 필수 동의 있음 (FR-A03)

3. 진행 중인 활동 없음, 이전 활동의 종료 확인됨

- **별도 시작 준비 화면은 없다.** 하나라도 확인되지 않으면 홈(04)의 자유대화·연습 탭을 잠그고, 누르면 이유를 보여준 뒤 05로 안내한다(필수 동의가 없으면 02, HOME-S04-002). 진행 중이면 두 탭은 새 시작 대신 그 세션의 진행 화면(12·21)으로 간다. 시작 요청(08 「자유대화 시작」, 18 「연습 시작」) 때 보호자 서버가 다시 확인한다. 04의 기기 상태 줄이 초록(연결됨)이 아니면(끊김·응답 없음·연결된 기기 없음) 준비되지 않은 것으로 본다.

- 요청 중 중복 제출을 막는다. 시작 요청 전송·서버 수락·기기 시작 확인을 구분하고 응답 미수신을 성공으로 표시하지 않는다.

- 시작을 누르기 전에 08·18을 떠나면 기기에 아무것도 보내지 않는다. 21 '상황 준비 중'의 「취소」도 기기에 아무것도 보내지 않고 시작 요청을 취소한다(ACT-S18-001).

- 수락 후 아이가 참여하기 전(12·21의 '참여 기다리는 중')에는 보호자가 「끝내기」(P1)로 준비를 취소할 수 있다. 취소 사실·시각만 남기고 대화 내용은 저장하지 않는다. 준비 취소와 아동의 참여 수락이 겹치면 **보호자 서버에 먼저 도착한 쪽**을 기준으로 처리하고, 참여가 먼저면 앱에 "이미 활동이 시작됐어요"와 활동 종료(P1) 경로를 안내한다.

- 배경 정보는 시작 필수가 아니다. 연습은 27에서 담은 목표가 있어야 시작한다(예시 목표 없음, CR-GOAL).

- 오래된 상태를 현재 준비 완료로 쓰지 않는다. 준비 판정 시간·상태 유효시간은 ADR.

### 4.3 CR-END — 종료 요청·종료 처리 중·종료 확인

종료 계기: 보호자 종료(P1) / 아동 종료 의도 확인(VOICE-STOP-001) / 정상 마무리 / 공백 자동 종료(SYS-GAP-001) / 기술 종료(VOICE-ERR-001) / 동의 철회(CONS-S02-002)

→ 아동 서비스: 종료 처리 중(ending)으로 전환, 보호자 서버에 전달

→ 기존·대기 출력, 새 질문, 연습 진행, 진행 중인 판정 턴, 일반 응답 중단 (SYS-PLAY-001)

→ 기술 종료를 뺀 모든 종료(정상 마무리·아동 종료 의도·보호자 종료·공백 자동 종료·동의 철회, 시작 안내 뒤의 무응답·참여 거절·준비 취소)에서 승인 마무리 문구 1회 (VOICE-END-001)

음성 대화 장애 중에는 대화용 마무리 응답을 새로 만들지 않음

→ 출력 중지·음성 모델 세션 종료 확인 = 종료 확인

→ 보호자 서버: 종료 사유·확인 시각·확보 기록 범위 저장 → 결과 정리 → 17·23

기술 문제 종료만 P2 안내 후 17·23. 아동 중단·공백 자동 종료·보호자 종료는 팝업 없이 17·23. 동의 철회로 끝나면 02 관리 모드에서 04로 간다

시작 전 미참여는 P3 안내만 하고 기록하지 않음. 참여 전 준비 취소는 취소 사실·시각만 남기고 종료 사유를 두지 않으며 26에 표시하지 않음

- 보호자 앱(P1·12·21)의 표시는 세 단계를 구분한다: **전송하지 못함**(부모 앱 연결 장애) / **끝내는 중**(종료 요청됨·종료 처리 중, 서버 접수) / **기기 종료 확인됨**.

- 종료 확인을 받지 못하면 "종료 확인 안 됨"과 마지막 확인 시각·원격 제어 한계를 표시하고 새 활동 시작을 막는다.

- 통신 장애 중 원격 즉시 종료를 보장하지 않는다.

- **P2는 기술 문제 종료(연결 끊김·복구 실패)만 알린다**. 공백 자동 종료·아동 중단은 보호자 재확인 없이 종료 확인 후 바로 17·23으로 전환한다.

- **종료 사유는 27 기록 상세에서만 보여준다.** 17·23은 종료 사실과 기록 정리 상태만, P2·P3는 제목과 「확인」만 보여준다.

### 4.4 CR-CONN — 연결 장애·기술적 일시 정지·복구

| 상황 | 아동 서비스 | 부모 앱 표시 |
|---|---|---|
| 음성 대화 장애(기기 연결 또는 음성 모델 연결) 확인 | 기술적 일시 정지: 기존·지연 응답 전달과 새 대화용 음성 전송 중지, 진행 중인 판정 턴 취소, 복구 시도. 기기 연결이 끊기면 아동 기기도 재생을 스스로 멈추고 T19를 '연결 끊김·다시 연결 중'으로 바꿈 | 12/21 대화 흐름에 **'잠깐 끊김'**(시각 구간) 하나. 04·05 기기 상태 줄은 대상별(기기 연결 끊김, 음성 모델 연결 문제는 기기 연결 줄의 세부 문구) |
| 복구 성공 | 종료 전이고, 미해결 종료 요청이 없고, 활동 상태·대화 맥락을 정상 복원할 수 있을 때만 재개. 끊기기 전 응답을 이어 재생하지 않음 | '잠깐 끊김' 구간을 닫고 확보된 이력으로만 갱신, 불명 구간은 미확인 |
| 복구 실패·복원 불가 | 기술 문제로 종료하고 종료 확인, 보호자 서버에 종료 사실·확보 기록 범위 전달 | 종료 확인 후 P2 → 17/23, 푸시 "연결 문제로 활동이 종료됐어요." |
| 보호자 서버가 상태 미수신 | 활동 계속, 미전달 상태·기록·전사 보관 후 재전달 | 04·05 **'응답 없음'(회색)** + 마지막 확인 시각(내부 상태 '기기 상태 확인 불가'). 12/21은 그 구간을 '잠깐 끊김'으로 표시하고(내부에서는 미확인 구간으로 구분) 재전달되면 실제 전사로 채움. 대화 중단으로 단정하지 않음 |
| 부모 앱 연결만 장애 | 영향 없음 | "실시간 상태를 불러오지 못하고 있어요" + 마지막 확인 시각·상태. 재조회 후 그동안의 전사를 이어 붙임. 조작 요청은 전송하지 못함으로 표시 |

- 장애 판정 시간·복구 대기시간·재시도 횟수·재개 판정 조건은 ADR(D-CON-03·05·07).

- 기술적 일시 정지는 12·21의 상태 변형이며 별도 화면으로 이동하지 않는다. 12·21은 '잠깐 끊김' 구간으로, 04·05는 끊김(빨강)·응답 없음(회색)으로 표시한다.

- 음성 대화 장애 중 아동에게 들려줄 고정 안내는 기술적으로 가능하나 제공 여부·문구·횟수는 결정 필요(요구사항 D-CON-09, 팀 결정 대기 TD-01). 결정 전에는 제공하지 않는다.

- 불명확 발화·침묵·마이크 문제·AI 지연·제브 응답 지연을 연결 장애로 일괄 판정하지 않는다.

### 4.5 CR-GAP — 오래 말이 없을 때 (FR-F18)

- 적용 조건: 기기 연결·음성 모델 연결이 정상이고, 활동 진행(12·21) 중이며, 아동 서비스가 기기 연결로 받은 음성 기준으로 공백의 연속성을 확인할 수 있을 때.

- **연속 4분 공백** → 아동 서비스의 내부 공백 상태. 보호자 화면에는 별도 상태로 표시하지 않는다. **추가 기본 2분**(총 약 6분) 지속 → 자동 종료. 종료 확인 후 팝업 없이 17·23으로 가고 종료 사유는 27에서 본다.

- **종료 사유 판정**

  - 공백 전에 아동의 **휴식 요청**(쉬고 싶다는 말 등)이 없었으면 → **대화 거부**.

  - 휴식 요청 뒤 이어진 공백이면 → 대화 거부로 보지 않고 '비정상 오디오 공백 지속'.

  - 휴식 요청은 VOICE-STOP-001(J6 '휴식 요청')·VOICE-START-001(J1 '휴식 요청')이 종료 의도와 구분해 기록한다. 휴식 요청 뒤에도 대화를 멈추지 않고 이어간다.

- 제외: 12·21의 시작 안내 중('참여 기다리는 중', 별도 규칙 CR-WAIT), 17·23 기록 정리, 종료 상태, 확인된 장애·상태 미확인·기술적 일시 정지 시간(합산하지 않음). 4분+2분을 장애 판정·복구 타임아웃으로 쓰지 않는다. 기술 문제로 반응을 확인할 수 없는 시간은 대화 거부의 근거가 아니다.

- 앱 닫힘·탭 이동은 타이머를 바꾸지 않는다. 정상 오디오가 돌아오면 연속 공백은 끝난다.

- 상태 전환 때 타이머의 세부 초기화·재시작은 결정 필요(요구사항 D-CON-10, 팀 결정 대기 TD-12).

- 4분 공백 동안 기기가 다시 말을 걸지(재안내)는 정하지 않았다(TD-04 후속).

- 27의 종료 사유 표시 문구는 아이를 탓하지 않게 콘텐츠 검수에서 정한다(CR-SAFE).

### 4.6 CR-STOP — 아동 종료 인식: 키워드 + 말의 뜻 (FR-E05)

| 단계 | 판단 | 처리 |
|---|---|---|
| ① 키워드 (기본) | 아이 발화의 GPT Live 입력 전사가 기본 표현 "무중아 그만할래" 또는 해당 아동의 저장된 추가 표현과 일치(아동 서비스가 전사에서 먼저 확인) | **바로 종료** 처리 중으로 전환 |
| ② 말의 뜻 (추가) | 키워드가 아니어도 제브 J6이 **종료 명확**으로 판정 | 종료 처리 중으로 전환 |
| ③ 불명확 | J6 '불명확'(또는 판정 보류) | 짧게 확인 질문 → 그렇다고 하면 종료 |
| 종료 아님 | J6 '종료 아님': 역할 속 대사, 상대 발화, 단순 주제 거부, 기기 재생 음성 | 대화·연습 발화로 처리 |
| 휴식 요청 | J6 '휴식 요청': 쉬고 싶다는 말 | 종료로 보지 않고 휴식 요청으로 기록(CR-GAP 판정에 사용). 무중이 짧게 받아주고 대화는 이어간다 |

- 키워드 일치가 유일한 종료 조건은 아니다(FR-E05와 맞음). 키워드는 확인 질문 없이 바로 처리하는 경로다. SET-01 화면에는 이 규칙의 안내 문구를 두지 않지만 동작은 같다.

- 확인 질문 문구·횟수, 확인 질문에 답이 없을 때 처리는 승인 콘텐츠로 정한다(§9 G-08). J6을 어떤 발화에 돌릴지와 일반 턴 자동 응답과의 순서는 §9 G-16.

- 건너뛰기·재개 음성 제어는 제공하지 않는다.

### 4.7 CR-RESULT — 종료 안내와 기록 상세의 분리

- 종료 직후 화면에는 다음만 보여준다: **P2**(기술 문제 종료) 제목 "대화가 예상치 못하게 끝났어요" + 「확인」 / **P3(시작 전 미참여) 제목 "아이가 대답하지 않아 시작하지 못했어요"(참여 거절이면 "아이가 지금은 하지 않기로 했어요") + 「확인」** / **17·23** 종료 사실(시작~끝 시각·길이, 연습은 목표 수)과 기록 정리 상태. 종료 사유·대화 요약·해석·추천 목표·장면 결과는 보여주지 않는다.

- 결과와 종료 사유는 **27 활동 기록 상세**에서만 확인한다. 17은 「오늘 기록 보기」, 23은 「오늘 연습 기록 보기」로 정확한 세션의 27에 들어간다. 이 버튼은 기록 정리가 끝나거나 실패하면 켜진다. P2는 「확인」 후 17·23으로 간다. 결과가 준비돼도 자동 이동하지 않는다.

- 27의 구성: '대화 기록' 칸(대화 전사 전체), '생활 팁' 칸(활동마다 최대 2개), '연습 목표' 칸(목표 후보), 연습이면 목표별 장면 결과 칩과 결과 문장, 종료 사유·확보 범위.

- 결과 상태: 준비 중 / 전체 결과 / 부분 결과 / 자료 부족·결과 없음 / 생성 실패. 생성 실패는 27에서 다시 요청(FR-F17).

- 자료 부족은 27에서 '자료 부족'으로 표시하고, 확보된 대화 전사는 '대화 기록' 칸에 그대로 보여준다. 별도 실패 리포트는 두지 않는다.

- 결과 유효 기준: 연습은 기회 문장 뒤 첫 반응이 1개 이상 기록되면 결과 생성 대상이다. 자유대화의 유효 기록 기준은 AI 상세 명세에서 정한다.

### 4.8 CR-PRACTICE — 연습 흐름 (공통규칙 '연습 분기', 2안 「상황 반응 조절형」)

목표마다 같은 흐름이며, 목표가 여러 개면 세션 계획 순서대로 같은 활동에서 이어 간다(CR-GOAL).

1 장면 시작 무중이 상대·활동·필요한 것을 짧게 설명하고 역할놀이(장면)를 시작 (VOICE-PRAC-001)

정답 표현을 먼저 주지 않는다

2 기회 기회 문장(자동 확인·J7을 통과해 세션에 고정한 문장) → 아이 반응 → 판정 턴 J2 (PRAC-RESP-001)

충분히 전달 → 교정 없이 대화를 이어 간다

일부 전달 → 상대 역할로 자연스럽게 1회 되묻기 → J3 (PRAC-ASK-001)

전달됨 → 이어 간다 (기록 '되묻기 뒤 전달', 별도 연습 없음)

여전히 부족 → 집중 연습 제안(동의 J4)

도움 요청 → 집중 연습

상황 이해 못함·무관 → 표현 교정 없이 상황 설명을 쉽게 바꿔 다시 제시 (PRAC-ASK-001)

판독 불가·판정 보류 → "다시 말해 줄래?"처럼 확인. 이를 근거로 교정하지 않는다

3 집중 연습 "잠깐, 무중이 도와줄게" → 코치 역할로 목표 관련 부분 하나만 짧게 (표현 예시 허용, PRAC-CUE-001)

→ 다시 해 보기 J5 → "다시 친구 역할로 돌아갈게" → 원래 장면 복귀 또는 정리 (PRAC-RESP-002)

4 변형 장면 장면 정리 후 시간·참여 의사가 남으면 한 요소를 바꾼 변형 장면 제안 (같은 놀이 주제의 다음 장면도 됨)

집중 연습이 길어졌거나 목표가 10분(임시)에 이르렀으면 생략 (PRAC-SCEN-002)

5 다음 목표 다음 목표가 있으면 같은 활동에서 이어 감 (PRAC-NEXT-001) → 마지막에 마무리 한 번 (VOICE-END-001)

- 되묻기·집중 연습·변형 장면은 **반드시 거치는 단계가 아니다.** 아이 반응과 남은 시간·참여 의사에 따라 고른다. 미실시·시간 종료는 실패가 아니다.

- 첫 반응 전에는 정답·시범·표현 예시를 주지 않는다(같은 말 반복·속도 조절만). 표현 예시는 집중 연습 안에서 목표 관련 부분 하나에 대해서만 준다(FR-E08, CR-SAFE).

- 판정은 제브가 하고(CR-JUDGE), 대화 역할에는 판정 결과가 아니라 다음 행동 지시만 준다. 친구·코치 역할 전환도 지시로 한다(VOICE-ROLE-001).

- **기록: 목표마다 '장면별 결과'와 '제공한 도움'(되묻기·집중 연습·상황 재설명·판정 보류 확인)을 남긴다. 장면별 결과는 목표 행동이 나온 장면이면 시점(바로 / 되묻기 뒤 / 도움 뒤) + 목표 행동 표현(목표마다 정하며 기본 '전달')이고, 목표 행동 없이 정리한 장면은 '다음 기회로', 끝까지 판정하지 못한 장면은 '보류', 하지 못한 장면은 미실시와 사유(시간 종료 등)다(요구사항 라벨정의 '장면 결과'). 27은 목표별 장면 결과 칩(예: "장면 1 · 도움 뒤 전달", "장면 2 · 시간 종료", "장면 1 · 바로 기다림")으로 보여준다. 판정 보류 때의 무난한 되묻기·다시 말해 달라는 확인은 '판정 보류 확인'으로 남기고 시점을 바꾸지 않는다('되묻기'는 일부 전달 때 상대 역할의 되묻기만 뜻한다). 기록용 판정값과의 대응: functional → 시점 + 목표 행동 표현, partial·none으로 정리 → '다음 기회로', uncertain → '보류', 판정할 반응 없음 → 미실시와 사유.**

- **다음 회차**에는 그 기록을 참고해 비슷한 장면이나 변형 장면을 제안한다(SYS-PRAC-001).

- **목표당 시간**은 10분(임시값, ADR에서 바꿀 수 있음)이다. 한 목표가 10분에 이르면 변형 장면을 더 하지 않고 그 목표의 장면을 정리한 뒤 다음 목표나 마무리로 간다(PRAC-SCEN-002·PRAC-NEXT-001, §8).

- 아동은 어느 때든 종료 의사를 표현할 수 있다(CR-STOP). 기술적 일시 정지 중에는 대화용 재안내·되묻기·집중 연습을 재생하지 않는다.

- 근거: Notion 「무중 「연습 대화」 커리큘럼 제안」 2안. 단 한 활동에서 여러 목표를 이어서 진행한다(2안의 "한 회차 목표 하나" 전제는 쓰지 않는다).

### 4.9 CR-JUDGE — 진행 중 반응 판정: 판정 모델 제브 (FR-F20)

**모델 역할**

| 모델 | 맡는 일 | 때 |
|---|---|---|
| GPT Live | 실시간 음성 대화(친구·코치 역할), 진행 중 실시간 도움, 아이 발화 입력 전사·무중 발화 출력 전사 제공 | 활동 중 |
| 제브 (판정 모델) | 진행 중 판정만. 미리 정한 선택지 중 하나를 확률(보정된 신뢰도)과 함께 반환. 비LLM, 텍스트만 입력, 응답 시간 후보값 약 70~500ms(확정 아님) | 활동 중(판정 턴), 활동 전(J7) |
| 분석 AI (텍스트 LLM) | 연습 목표 후보·4요소, 장면·기회 대본, 경험 구조화, 기록용 재판정, 27 결과 문장·생활 팁, 리포트 | 활동 전·후(지연 허용) |

**판정 흐름**은 §1.4. 판정 턴(기회 문장 직후 등)에서만 아동 서비스가 GPT Live 자동 응답을 보류하고, 일반 턴은 자동 응답을 그대로 쓴다. 판정 입력은 GPT Live 입력 전사만 쓴다(별도 STT 없음).

**판정 지점과 선택지**

| 지점 | 언제 | 선택지 | 다음 행동 |
|---|---|---|---|
| J1 | 시작 안내 응답 | 참여 / 휴식 요청 / 거부 / 무관·불명확 / 판독 불가 | 참여 → 활동 시작. 휴식 요청 → 기록하고 안내를 이어 감. 거부 → VOICE-DECLINE-001. 무관·불명확·판독 불가 → 참여 의사를 다시 확인 |
| J2 | 기회 직후 반응 | 충분히 전달 / 일부 전달 / 도움 요청 / 상황 이해 못함 / 무관 발화 / 판독 불가 | CR-PRACTICE 2 |
| J3 | 되묻기 뒤 반응 | 전달됨 / 여전히 부족 / 도움 요청 / 판독 불가 | 이어 감 / 집중 연습 제안 / 집중 연습 / 확인 |
| J4 | 도움 동의 | 수락 / 거절 / 불명확 | 집중 연습 / 장면을 이어 가거나 정리 / 시작하지 않음(교정 없음) |
| J5 | 집중 연습 뒤 재시도 | J2의 선택지 + 코치 표현 그대로 따라 함 | 기록 후 원래 장면 복귀 또는 정리 |
| J6 | 종료 의도 (키워드 불일치 시) | 종료 명확 / 불명확 / 종료 아님 / 휴식 요청 | CR-STOP. 키워드("무중아 그만할래"·등록 표현)는 전사에서 먼저 확인해 바로 종료 |
| J7 | 생성 대본 사전 점검 (FR-F07) | 정답 문장 포함 / 첫 반응 전 단서 / 평가·압박 표현 / 통과 | 통과만 세션 대본으로 씀. 나머지는 다시 생성(SYS-PRAC-001) |

- **확신 문턱**: 1순위 확률이 낮거나 1·2순위 차이가 작으면 **판정 보류** → 교정 없이 되묻기. 문턱값은 검증 과제다(PoC로 확인하며 팀 결정 항목이 아님).

- **시간 제한·대체 경로**(ADR 값): 전사가 제한 시간(예 1.5초) 안에 오지 않으면 판독 불가로 처리, 제브가 제한 시간(예 800ms) 안에 응답하지 않으면 판정 보류 → 무난한 되묻기 지시. 늦게 온 전사·판정은 진행에 쓰지 않는다(SYS-JUDGE-003). 응답 공백 허용 시간은 10초(임시값)다. 아이 말이 끝난 뒤 10초 안에 응답이 준비되지 않으면(예: 전사나 제브 판정이 늦음) 판정 보류로 처리하고 무난한 되묻기나 맞장구로 응답한다. 위 제한 시간 예시(1.5초·800ms)는 이 10초 상한 안의 ADR 값이다.

- **FR-F15 적용**: 판정 기준과 판정 결과(라벨)는 대화 역할(GPT Live)에 주지 않는다. GPT Live에는 '다음 행동 지시'만 준다.

- **기록**: 진행 중 판정(판정 지점·선택지·확률·보류 여부)은 진행용으로 남긴다(SYS-JUDGE-004). 활동 뒤 분석 AI가 전체 전사로 다시 판정해 27 기록을 확정한다(기록용 재판정, SYS-EVAL-001).

- 판정은 그 장면의 반응 판정이며 능력·진단을 뜻하지 않는다. 진행 중 판정값·확률은 보호자 화면에 보여주지 않는다.

- **검증 과제(PoC로 확인, 팀 결정 항목 아님)**: 제브 한국어 아동 발화 정확도, 확신 문턱값. ADR: 전사·제브 제한 시간(응답 공백 허용 시간 10초 상한 안), 공백이 2초를 넘을 때 맞장구 문구 여부, 아이 기기 에코 제거. 예상 응답 공백 1.1~2.5초는 추정치다.

### 4.10 CR-WAIT — 무응답

- 연결·마이크·AI 지연으로 반응을 확인할 수 없는 경우는 아동 무응답과 구분한다. 전사가 제한 시간 안에 오지 않은 것(판독 불가)과 제브 시간 초과(판정 보류)도 아동 무응답이 아니다.

- **연습** (정상 진행): 기회 직후·되묻기 뒤에 반응이 없으면 1회 재안내 → 그래도 반응이 없으면 그 장면 미실시. 무응답을 능력 부족으로 보지 않는다. 반응이 있으면 제브로 판정한다(J2·J3·J5).

- **자유대화 진행 중**: CR-GAP을 따른다. 휴식 요청 없이 공백이 이어지면 대화 거부로 종료.

- **시작 안내 중 (12·21의 '참여 기다리는 중')**: 자유대화와 같은 규칙. 응답이 있으면 제브 J1로 판정한다. 휴식 요청 없이 답이 없으면 시작 전 아동 미참여로 종료하고(P3, 기록 없음, 승인 마무리 문구 1회), '쉬고 싶어'(J1 휴식 요청)는 거부로 보지 않고 휴식 요청으로 기록한다. 시작 단계의 대기 시간은 ADR(§8). 휴식 요청 뒤에도 시작 안내를 이어간다.

- 대기값은 ADR. 잠정값(실제 재생 완료 후 10초에 1회 재안내, 재안내 후 10초 추가 대기)은 ADR 후보다.

### 4.11 CR-GOAL — 연습 목표: 후보·담기·선택·순서·다음 회차 (FR-C01~C03·F06·F19)

- **목표는 기록에서 나온다.** 분석 AI가 자유대화·연습 기록을 보고 연습할 화용 행동 후보를 만들고, 후보마다 **핵심 기능 정의·연습 기회 조건·상황 생성 조건·반응 판정 기준**(4요소)을 만들어 저장한다. 4요소를 갖춘 후보만 27의 '연습 목표' 칸(자유대화·연습 기록 모두)에 추천 이유·근거 기록(발화·시각)과 함께 보여준다. 사람의 별도 검토 없이 보호자에게 표시한다. 근거가 부족하면 후보를 만들지 않고 '후보 없음'으로 표시한다.

- **보호자가 「담기」한 후보만 연습 목표가 된다.** 담은 목표는 18 '내 연습 목표'에 쌓이고, 목표마다 담은 곳(날짜·활동)·연습 횟수·지난 연습 기록(장면 결과·제공한 도움)을 보관한다. 18에는 담은 곳과 연습 횟수를 보여준다. ★로 즐겨찾기를 지정·해제하고, 길게 눌러 지운다(확인 후).

- **미리 넣어 두는 기본·예시 목표는 없다.** 담은 목표가 없으면 18은 안내와 「자유대화 하러 가기」(08)만 보여준다.

- **여러 목표를 한 활동에서 이어서 연습한다.** 18에서 하나 이상 골라 시작한다. 순서는 즐겨찾기와 담은 순서에 가중치를 둔 무작위로 정하고(가중치 ADR) 시작 요청 때 세션 계획에 고정한다. 목표마다 장면 대화(CR-PRACTICE)를 진행하고, 끝나면 아동 서비스가 다음 목표의 장면으로 대화 지침을 바꿔 같은 활동에서 이어간다(PRAC-NEXT-001). 마무리는 마지막에 한 번.

- **다음 회차 제안**: 지난 연습 기록(장면 결과·제공한 도움)을 참고해 비슷한 장면이나 한 요소를 바꾼 변형 장면을 제안한다(SYS-PRAC-001).

- **권장 연령은 고려하지 않는다.** 목표에 연령 정보를 두지 않고 후보 추천에도 쓰지 않는다.

- 기회 문장은 상황 생성 후 자동 확인과 제브 J7 사전 점검(SYS-PRAC-001)을 통과한 문장을 그 세션의 고정 대본으로 쓴다.

- 생활 팁(FR-C09)은 활동마다 분석 AI가 만드는 것으로 연습 목표 목록과 별개다.

### 4.12 CR-RECORDING — 생활 대화 녹음 (FR-B04): MVP 제외, 확장 틀만

**FR-B04는 Won't이며 MVP에서 제외한다**. 녹음 화면·첨부 칸(시안 08의 녹음 첨부 포함), 업로드, 저장, 분석은 만들지 않는다. 나중에 다시 넣을 때 구조를 바꾸지 않도록 아래 틀만 둔다.

| 틀 | MVP에서 하는 것 | 나중에 추가할 것 |
|---|---|---|
| 자유대화 준비 | 08 하나에서 입력하고 시작한다. 준비 입력을 항목 목록으로 관리해 08에 칸을 더하거나 08 다음 단계를 끼울 수 있게 둔다 | 생활 녹음 첨부 |
| 세션의 참고 자료 연결 | 자유대화 세션에 '참고 자료' 목록(비어 있음)을 연결할 수 있는 구조만 둔다 | 녹음 파일 연결 |
| 출처 태그 | 값 목록에 '생활 녹음'을 예약해 두되 쓰지 않는다. MVP 출처는 보호자 입력 / 아동 회상 | 생활 녹음 출처 표시 |
| 동의 항목 | 항목별 동의를 항목 목록으로 관리해 항목을 추가할 수 있게 둔다 | 생활 녹음·제3자 음성 동의 |
| 삭제 대상 | 삭제 대상(원음·전사·리포트)을 목록으로 관리해 확장할 수 있게 둔다 | 생활 녹음 |

- 정책(동의·제3자 음성·파일 조건·보관·대화 활용)은 다시 넣을 때 정한다. 팀 결정 문서의 생활 녹음 설명과 단순안을 그때 쓴다.

### 4.13 CR-PUSH — 푸시 알림 (FR-A10)

| 확인된 사실 | 문구 |
|---|---|
| 음성 대화 장애 확인 | "대화 중 음성 연결 문제가 발생했어요." |
| 기기 상태 미확인 | "기기 상태를 확인할 수 없어요." |
| 기술 문제로 종료 확인 | "연결 문제로 활동이 종료됐어요." |

- 감시와 발송 요청은 보호자 서버가 하며 앱 실행 여부와 무관하다. 앱 닫힘·부모 앱 연결만 장애는 알림 사유가 아니다.

- 발송 요청·실패·전달 상태를 구분한다. 실제·즉시 전달을 보장하지 않는다.

- 같은 사건의 중복 발송을 막는다. 발화 원문·대화 내용은 넣지 않는다.

- 알림 선택·앱 재진입 시 최신 세션을 다시 조회해 12/21(진행·종료 처리 중), 17/23(종료 확인됨, 기술 문제 종료는 P2 안내 후)로 연결한다. 오래된 알림 문구로 현재 상태를 덮지 않는다.

- 발생 기준·중복 억제·복구 안내는 ADR(D-CON-06).

### 4.14 CR-DATA — 동의·보존·삭제

- 항목별 동의 4개(음성 수집(전사를 위한 처리)·전사 저장, 보호자 열람, 리포트 생성·외부 전달, 원음 보관)는 모두 필수이고, 처음에는 넷 모두 동의해야 진행한다. 동의 여부에 따라 기능을 나누지 않는다. 항목마다 세부(수집하는 것·이용 목적·보관·동의하지 않으면)를 02-1 시트로 보여준다(CONS-S02-004).

- **보호자 열람 범위**에는 27의 대화 전사 전체와 12·21의 실시간 대화 전사가 들어간다. 실시간 전사 중계는 전사 저장과 같은 동의 조건을 따른다(SYS-LIVE-001).

- 동의 철회(네 항목 중 하나라도 해제): 별도 확인 → 진행 중 활동 종료(종료 사유 '동의 철회') → 이후 수집·이용·실시간 중계 중단. 철회 전 정상 저장된 기록은 유지하며 모두 열람할 수 있다(보호자가 따로 삭제 가능). 철회로 끝난 활동은 철회 전까지의 대화 기록만 남고 결과(생활 팁·목표 후보·장면 결과)는 만들지 않는다(결과 상태 '결과 없음'). 철회 후 새로 오거나 늦게 도착한 자료는 철회 전 발화라도 저장하지 않는다. 철회 후 기존 기록은 **열람과 삭제만** 허용하고 새 분석·리포트 생성·외부 전달은 하지 않는다.

- 기록 삭제: 대상(원음·전사·리포트) 선택 → 영향 안내 → 삭제 확인. 그 기록에서 만든 목표 후보·요약·생활 팁·리포트·진행용 판정 기록도 함께 지운다.

- **아동 삭제 (FR-A12)**: 03 카드 「삭제」 → P4 확인 → 아동 삭제. 기본안은 그 아동의 기록(전사·원음·활동 기록·판정 기록·결과·생활 팁·리포트)·연습 목표(후보·담은 목표)·종료 표현 설정을 함께 지우며 되돌릴 수 없다. 기록을 함께 지울지는 결정 필요(TD-20)이며 결정 전에는 기본안으로 구현한다. 진행 중이거나 종료가 확인되지 않은 활동이 있는 아동은 삭제할 수 없다. 삭제하면 03 첫 등록(빈 카드)으로 가며 동의와 아이 기기 등록은 계정에 남는다. 삭제 뒤 늦게 도착한 그 아동의 자료는 저장하지 않는다.

- **계정 삭제 (FR-A13)**: SET-00 「계정 삭제」 → 확인 → 계정과 아동·기록 삭제 → 01. 진행 중 활동이 있으면 종료 확인 뒤 삭제한다. 그 계정의 기기 등록과 기기 토큰은 무효가 된다.

- 원음·전사·활동 기록·진행용 판정 기록·상태 이력은 모두 **보호자 서버**에 저장한다. 아동 서비스는 진행 중 상태와 전달 대기 데이터만 임시 보관한다(보관 한계 ADR).

- 시작 전 미참여는 기록을 남기지 않는다(종료 사실·시각 포함, 거부 발화 원문·참여 기다리는 중의 전사·판정 기록 미저장). 보호자에게는 그 자리에서 P3로만 안내한다. 진행 관리에 쓴 세션 상태를 언제 지울지는 ERD·ADR에서 정한다.

### 4.15 CR-SAFE — 표시·생성 금지 (NFR-01·09, 공통규칙 '표시·생성 금지')

진단명·진단 가능성, 사회성·화용능력 점수·등급·백분율·향상률·성공률, 치료효과·치료 권고, 결함 확정 표현, 실제 생활 일반화 단정, 아동·상대 아동의 의도·감정·성격 단정(아동이 직접 말한 것은 인용으로만), 지원 효과 보장·정답 강요, 연속 이용·완료 압박을 화면·리포트·기기 음성 어디에도 만들지 않는다. 기기 음성에서는 사람인 척, 비밀 약속, 잘함/못함 평가, 보호자 입력 직접 언급도 금지한다.

- **정답 문장·시범·표현 예시**: 첫 반응 전에는 금지한다. 집중 연습(코치 역할) 안에서 목표 관련 부분 하나에 대한 짧은 표현 예시만 허용하며, 아이가 요청하지 않은 도움은 동의(J4) 뒤에만 준다. 따라 하도록 다그치는 정답 강요는 그대로 금지한다.

- 생성 결과(장면·기회 대본, 27 결과 문장, 생활 팁, 리포트)는 자동 검사를 통과한 것만 쓴다. 장면·기회 대본은 제브 J7로 사전 점검한다(정답 문장 포함·첫 반응 전 단서·평가·압박 표현이면 쓰지 않음). 생활 팁 검사 기준은 미결(§9.2).

- 12·21의 대화 흐름과 27의 대화 기록은 전사를 그대로 보여줄 뿐 아동 평가 표시(색·점수·판정값)를 붙이지 않는다. 진행 중 판정값·확률은 보호자에게 보여주지 않는다.

- 02의 생성형 AI 고지와 29의 '진단 결과가 아님' 안내는 화면에 회색 설명 글을 두지 않는 원칙의 예외로 반드시 둔다.

#### ACT-S12-001 — 자유대화 진행 화면·실시간 대화 전사

| 항목 | 명세 |
|---|---|
| 화면 | 12 |
| 요구사항 | FR-B06, FR-F18, FR-A06, FR-A10, FR-F01 |

| 입력 | 아동 서비스의 활동 상태·실시간 대화 전사(SYS-LIVE-001)·연결 관측, 보호자 서버의 수신 여부·마지막 확인 시각, 부모 앱 조회 가능 여부 |

| 주체 | 부모 앱(표시), 보호자 서버(중계·저장), 아동 서비스(전사·관측) |
| 검증 | 대화 중 무중·아이 발화가 시각과 함께 순서대로 보인다. 음성 대화 장애를 주입하면 '잠깐 끊김' 구간 하나가 생기고, 앱만 오프라인이던 동안 계속된 대화는 재조회 후 실제 전사로 이어진다. 상태 미수신 구간은 재전달 후 실제 기록으로 바뀐다. 종료 확인 후에만 17(기술 문제 종료는 P2 안내 후)로 바뀐다 |

#### ACT-S18-001 — 연습 시작 요청

| 항목 | 명세 |
|---|---|
| 화면 | 18 → 21 |
| 요구사항 | FR-C05, FR-C02, FR-F07, 공통규칙 '활동 시작 조건' |
| 우선순위 | Must |
| 입력 | 대상 아동(그 계정의 아동), 고른 목표(1개 이상) |
| 처리 | 「연습 시작」을 누르면 중복 제출을 막고 보호자 서버가 CR-START 조건을 다시 검사한다. 고른 목표가 여럿이면 즐겨찾기와 담은 순서에 가중치를 둔 무작위로 순서를 정해(가중치 ADR) 세션 계획에 고정한다. 21로 가서 '상황 준비 중'(고른 목표 이름)을 표시하고, 목표마다 장면 대본과 기회 문장을 만들어 자동 확인과 제브 J7 사전 점검을 통과하면(SYS-PRAC-001) 세션을 등록 기기에 배정하고 아동 서비스에 시작을 전달한다(ACT-START-001). 개별 장면 대본 본문은 보호자에게 보여주지 않는다. '상황 준비 중'의 「취소」 → 기기에 아무것도 보내지 않고 시작 요청을 취소하고 18로 돌아간다 |
| 예외 | 대본 생성·점검 2회 실패 → 시작하지 않고 18로 돌아가 이유 안내(기기에 전달하지 않음). 목표가 여럿일 때 장면을 언제 만드는지와 실패 시 세션 처리는 TD-16. 부모 앱 연결 장애·기기 준비 미확인·이전 종료 미확인 → 시작 불가. 시작을 누르기 전 18을 떠나면 기기에 아무것도 보내지 않는다 |
| 검증 | 서버 수락을 기기 실행 확인으로 표시하지 않고 중복 없이 시작한다. 생성·점검 실패를 정상 생성으로 표시하지 않는다. 고른 목표와 순서가 세션 계획에 고정된다. 상황 준비 중 취소 뒤 기기는 아무것도 받지 않는다 |

#### PRAC-RESP-001 — 상황 대화와 첫 반응 (기회 문장·판정 턴)

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E07, FR-F20, FR-E04, 공통규칙 '연습 분기' |
| 우선순위 | Must |
| 주체 | 아동 서비스, GPT Live(친구 역할), 제브(판정) |
| 처리 | 장면 대화 중 기회 문장(상황 생성 후 자동 확인·J7 점검을 통과해 세션에 고정한 문장)을 그대로 출력하고, 아이가 먼저 반응할 때까지 힌트·정답·시범을 주지 않는다(같은 말 반복·속도 조절만). 기회 문장 직후 아이 발화는 판정 턴으로 처리한다(SYS-JUDGE-001, J2). 판정에 따라 다음 행동을 정한다: **충분히 전달** → 교정 없이 장면 대화를 이어 간다 / **일부 전달** → 상대 역할로 1회 되묻기(PRAC-ASK-001) / **도움 요청** → 집중 연습(PRAC-CUE-001) / **상황 이해 못함·무관 발화** → 상황 설명을 쉽게 바꿔 다시 제시(PRAC-ASK-001) / **판독 불가·판정 보류** → "다시 말해 줄래?"처럼 확인하고 교정하지 않는다. 질문 핵심이 재생되지 않았으면 그 기회를 무효로 한다. 첫 반응을 장면 기록에 남긴다 |
| 예외 | 무응답 → CR-WAIT(1회 재안내 → 그 장면 미실시). 기술적 일시 정지 중 재안내·도움 재생 금지. 종료 의도 → VOICE-STOP-001 |
| 검증 | 첫 반응 전 도움·정답·표현 예시 출력이 차단된다. 기회 문장은 세션 고정 대본 그대로 출력된다. J2 판정마다 정해진 다음 행동만 대화 역할에 지시된다 |

#### PRAC-ASK-001 — 되묻기·상황 다시 설명 (교정 없는 대응)

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E08, FR-F20, FR-E04 |
| 우선순위 | Must |
| 주체 | 아동 서비스(지시), GPT Live(친구 역할), 제브(판정) |
| 트리거 | J2 판정이 '일부 전달' 또는 '상황 이해 못함·무관 발화' |
| 처리 | **되묻기**(일부 전달): 상대 역할로 자연스럽게 1회 되묻는다. 다음 아이 발화를 J3로 판정한다: 전달됨 → 교정 없이 장면을 이어 가고 '되묻기 뒤 전달'로 기록(별도 연습 없음) / 여전히 부족 → 집중 연습을 제안(PRAC-CUE-001, 동의 J4) / 도움 요청 → 집중 연습 / 판독 불가 → 다시 말해 달라고 확인. **상황 다시 설명**(상황 이해 못함·무관 발화): 표현을 고쳐 주지 않고 상대·활동·필요한 것을 더 쉬운 말로 다시 설명한 뒤 기회를 다시 준다. 각 대응을 '제공한 도움'(되묻기·상황 재설명)으로 기록한다 |
| 예외 | 되묻기는 기회마다 1회. 되묻기·다시 설명에 정답 문장·시범을 넣지 않는다. 무응답 → CR-WAIT. 판정 보류(문턱 미달·시간 초과) → 교정 없이 무난한 되묻기(SYS-JUDGE-003). 상황 다시 설명의 횟수와 그 뒤 처리는 AI 상세 명세(§9 G-16) |
| 하지 않는 것 | 교정, 잘함/못함 평가, 정답 표현 제시 |
| 검증 | 일부 전달 사례에서 되묻기가 1회만 나오고 해결되면 집중 연습 없이 이어진다. 상황 이해 못함 사례에서 표현 교정 없이 설명만 바뀐다. 기록에 되묻기·상황 재설명이 남는다 |

#### PRAC-CUE-001 — 집중 연습 (코치 역할, 표현 예시 허용)

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E08, FR-F20, FR-E04, FR-F15 |
| 우선순위 | Must |
| 주체 | 아동 서비스(지시), GPT Live(코치 역할), 제브(동의 판정) |
| 트리거 | 아이가 도움을 요청함(J2·J3 '도움 요청'), 또는 되묻기 뒤에도 부족해 목표 관련 지원이 필요함(J3 '여전히 부족') |
| 처리 | 도움 요청이면 바로, 그 밖에는 짧게 동의를 묻고(J4: 수락 / 거절 / 불명확) 수락하면 시작한다. 아동 서비스가 대화 역할에 '코치 역할로 바꿔 목표 관련 부분 하나를 짧게 연습' 지시를 보낸다(VOICE-ROLE-001). 무중이 "잠깐, 무중이 도와줄게"처럼 역할을 바꿨음을 알리고 목표 관련 부분 하나만 짧게 연습한다. 필요하면 표현 예시를 줄 수 있다(예: 이렇게 말해 볼까? "무중아, 나도 같이 쌓아도 돼?"). 지시에는 판정 기준·판정 결과(라벨)를 넣지 않는다(FR-F15). 제공한 도움(종류·내용·표현 예시 여부·시각)과 동의 응답을 기록한다. 이어서 PRAC-RESP-002 |
| 예외 | J4 거절 → 집중 연습 없이 원래 장면을 이어 가거나 정리한다. J4 불명확·판정 보류 → 시작하지 않고 교정 없이 장면을 이어 간다. 첫 반응 전에는 시작하지 않는다(첫 반응 전 정답·시범 금지). 표현 예시는 집중 연습 안에서 목표 관련 부분 하나에 한한다(CR-SAFE) |
| 하지 않는 것 | 첫 반응 전 표현 예시, 여러 목표를 한꺼번에 연습, 평가·압박 표현, 따라 할 때까지 다그치기 |
| 검증 | 첫 반응 전에는 표현 예시가 나오지 않는다. 도움 요청 때는 동의 질문 없이, 그 밖에는 수락 뒤에만 집중 연습이 시작된다. 기록에 제공한 도움과 동의 응답이 남는다. 지시에 판정 라벨·기준이 없다 |

#### PRAC-RESP-002 — 집중 연습 뒤 다시 해 보기·원래 장면 복귀

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E08, FR-F09, FR-F20 |
| 우선순위 | Must |
| 주체 | 아동 서비스, GPT Live, 제브(판정) |
| 처리 | 집중 연습 뒤 무중이 "다시 친구 역할로 돌아갈게"처럼 알리고 친구 역할로 돌아가(VOICE-ROLE-001) 원래 장면의 기회를 다시 준다. 아이 반응은 J5(J2의 선택지 + '코치 표현 그대로 따라 함')로 판정해 기록하고 장면을 이어 가거나 정리한다. 집중 연습 뒤 반응은 첫 반응과 따로 기록하고 덮어쓰지 않는다. 목표당 시간이나 참여 의사가 남지 않았으면 복귀하지 않고 장면을 정리한다 |
| 예외 | 무응답 → CR-WAIT. 판독 불가·판정 보류 → 확인만 하고 교정하지 않는다. 같은 장면에서 집중 연습을 다시 할지와 횟수는 AI 상세 명세(§9 G-16) |
| 검증 | '코치 표현 그대로 따라 함'이 '충분히 전달'과 구분돼 기록된다. 첫 반응 기록이 바뀌지 않는다 |

#### PRAC-SCEN-002 — 변형 장면 제시

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E09, FR-F08 |
| 우선순위 | Must |
| 주체 | 아동 서비스, GPT Live(친구 역할). 대본은 분석 AI(SYS-PRAC-001) |
| 처리 | 장면을 정리했고 목표당 시간(10분, 임시값)과 아이의 참여 의사가 남아 있으면, 목표 행동과 기회 조건은 유지하고 한 요소를 바꾼 변형 장면을 제안한다. 같은 놀이 주제의 다음 장면으로 이어 붙여도 된다. 집중 연습이 길어졌으면 변형 장면은 생략한다. 한 목표가 10분에 이르면 변형 장면을 더 하지 않고 그 목표의 장면을 정리한 뒤 다음 목표나 마무리로 간다(PRAC-NEXT-001). 변형 장면에서도 첫 반응 전 정답·시범 금지와 같은 판정 흐름(PRAC-RESP-001)을 따른다. 장면 번호·종류(기본/변형)와 결과를 기록한다 |
| 예외 | 변형 장면 대본 없음·생성 실패·시간 부족·참여 의사 없음 → 생략(실패 아님). 아이가 원하지 않으면 이어 가지 않는다. 음성 인식·마이크 문제, 음성 대화 장애, 상태 확인 불가를 구분한다(VOICE-ERR-001) |
| 하지 않는 것 | 변형 장면을 반드시 거치는 고정 순서, 같은 활동에서 같은 장면 반복 |
| 검증 | 시간·참여 의사가 남은 경우에만 제안되고 집중 연습이 길었던 목표에서는 생략된다. 10분(임시)에 이른 목표에서는 변형 장면이 제안되지 않는다. 같은 활동에서 같은 장면이 다시 쓰이지 않는다 |

| 우선순위 | Must |

### 5.6 기록·리포트 (26~29)

#### HIST-S26-001 — 기록 달력

| 항목 | 명세 |
|---|---|
| 화면 | 26 |
| 요구사항 | FR-D01, FR-D04 |
| 우선순위 | Must |
| 처리 | 기록 탭을 달력으로 보여주고 활동(자유대화·연습)이 있는 날에 표시를 둔다. 날을 누르면 그날 활동을 시각 순으로(종류·길이·중간에 끊김 여부·결과 상태. '중간에 끊김'은 종료 사유가 정상 마무리가 아닌 모든 활동) 보여주고, 활동을 누르면 해당 세션 27로 간다. 상단 「상담용 리포트 다운」 → 28 |
| 예외 | 시작 전 미참여와 참여 전 준비 취소는 활동 기록이 아니므로 표시하지 않는다. 결과 준비 중·생성 실패도 목록에서 구분한다. 기록 없음 → 빈 달력과 다음 활동 선택(HIST-NAV-001) |
| 검증 | 활동한 날이 달력에 표시되고, 같은 날 여러 활동이 시각 순으로 구분되며 선택한 활동과 상세의 세션이 같다 |

#### HIST-S27-001 — 자유대화 기록 상세 (대화 기록 칸)

| 항목 | 명세 |
|---|---|
| 화면 | 27 (자유대화. '대화 기록'·'생활 팁'·'연습 목표' 칸) |
| 요구사항 | FR-D02, FR-F04, FR-F05, FR-F12, FR-B08, FR-F06 |
| 우선순위 | Must |
| 처리 | 맨 위에 날짜·종류·시작~끝 시각·길이를 보여주고 칸 세 개(대화 기록 / 생활 팁 n / 연습 목표 n)로 나눈다. **대화 기록** 칸에는 그 활동의 대화 전사 전체(무중·아이 발화, 시각)를 시간 순서대로 보여주고, 끊긴 구간은 '끊김'과 시각 구간으로, 전사의 불확실 구간은 불확실로 표시한다. 생활 팁 칸은 SUP-S27-001, 연습 목표 칸은 HIST-S27-005, 종료 사유·확보 범위는 HIST-S27-003 |
| 예외 | 동의 철회 뒤에도 철회 전에 저장된 전사는 그대로 보여준다(CR-DATA). 전사가 일부만 확보되면 확보된 부분만 보여주고 빈 구간을 만들어 채우지 않는다. 표현 제한 CR-SAFE(전사는 기록 그대로 보여주고 평가 표시를 붙이지 않음) |
| 하지 않는 것 | 전사 수정, 판정값·점수 표시, 보호자 입력 배경·경험 구조화 칸(리포트·목표 후보 근거에만 쓴다) |
| 검증 | 대화 기록 칸의 전사가 저장 전사와 시각까지 일치하고 수치·판단·점수가 없다. 끊김 구간이 실제 장애 구간과 같다 |

#### HIST-S27-002 — 연습 기록 상세 (목표별 장면 결과)

| 항목 | 명세 |
|---|---|
| 화면 | 27 (연습) |
| 요구사항 | FR-D02, FR-F09, FR-F10, FR-C07, FR-C09 |
| 우선순위 | Must |
| 처리 | 맨 위에 날짜·시작~끝 시각·목표 수를 보여준다. 목표마다(진행 순서대로) 장면 결과 칩(예: "장면 1 · 도움 뒤 전달", "장면 2 · 시간 종료", "장면 1 · 바로 기다림")과 분석 AI가 기록용 재판정(SYS-EVAL-001)으로 만든 결과 문장(예: 도움 뒤 "같이 쌓아도 돼?"라고 말했어요. 두 번째 장면은 시간이 다 돼 하지 않았어요)을 보여준다. 제공한 도움(되묻기·집중 연습·상황 재설명·판정 보류 확인)을 장면 결과와 함께 보여주고 기록의 한계를 덧붙인다. 아래에 대화 기록(전사 전체, HIST-S27-001과 같은 방식)·생활 팁(SUP-S27-001)·연습 목표(HIST-S27-005) 칸을 둔다 |
| 예외 | 되묻기·집중 연습·판정 보류·시간 종료·미실시를 실패·0점으로 바꾸지 않는다. 진행 중 판정과 기록용 재판정이 다르면 기록용 재판정을 보여준다 |
| 하지 않는 것 | 성공률·점수·확률, 진행 중 판정값 |
| 검증 | 목표마다 장면 결과 칩과 제공한 도움이 보이고 성공률·점수가 없다. 집중 연습 뒤 반응이 첫 반응을 덮지 않는다 |

#### HIST-S27-003 — 기록 상태·확보 범위 표시

| 항목 | 명세 |
|---|---|
| 화면 | 27 |
| 요구사항 | FR-D02, FR-F11, FR-F17, FR-A10 |
| 우선순위 | Must |
| 처리 | 결과 상태(준비 중 / 전체 / 부분 / 자료 부족·결과 없음 / 생성 실패)를 구분한다. 종료 사유(정상 마무리·아동 중단·보호자 중단·기술 문제·대화 거부·비정상 오디오 공백 지속·동의 철회)와 종료 시각을 맨 위 '끝난 이유' 칸에서 보여준다(17·23·P2에는 없음). 동의 철회로 끝난 활동은 결과 없이 대화 기록만 보여준다. 종료 사유 문구는 아이를 탓하지 않게 콘텐츠 검수에서 정한다. 기술 문제가 있었던 활동은 종료 확인 여부, 확보된 기록 범위, 상태 미확인 구간을 따로 보여준다. 부모 앱 연결이 복구되면 실제 받은 기록만 갱신한다 |
| 예외 | 확보되지 않은 기록을 만들어 채우지 않는다. 기록 수신 공백을 아동의 침묵·거부·실패로 해석하지 않는다. 자료 부족이어도 확보된 전사는 대화 기록 칸에 그대로 보여준다 |
| 검증 | 준비 중·생성 실패·자료 부족이 구분되고 종료 확인과 기록 정리·확보 범위가 구분된다. 같은 세션의 종료 사유가 P2·푸시 알림과 일치한다 |

#### SUP-S27-001 — 생활 팁 (활동마다 생성)

| 항목 | 명세 |
|---|---|
| 화면 | 27 '생활 팁' 칸 (자유대화·연습 기록 모두) |

| 우선순위 | Should (표현 제한 NFR-01은 Must) |

| 검증 | 자유대화·연습 기록 모두 팁이 0~2개 보이고, 금지 표현 검사에 걸린 팁은 보이지 않는다. 팁마다 실제 대화 장면이 근거로 연결된다 |

#### RPT-S28-001 — 리포트 범위 고르기·생성

| 항목 | 명세 |

### 5.7 아동 기기·음성 대화 (아동 서비스)

#### DEV-CLIENT-001 — 아동 기기 클라이언트 연결·재생

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-A06, FR-A11, FR-E11, NFR-06, NFR-11 |
| 우선순위 | Must |
| 주체 | 아동 기기 |
| 처리 | 등록 때 받은 기기 토큰으로 아동 서비스에 하나의 기기 연결을 맺고(DEV-REG-001) 배정된 활동에 참여하며 음성·상태·명령을 주고받는다. 실제 재생 구간을 보고한다. 기기 연결이 끊기면 받아 둔 응답 재생을 **즉시 스스로 멈추고**, 다시 연결돼도 끊기기 전 응답을 이어 재생하지 않는다. 아동 서비스가 보내는 표시 상태(대기·듣는 중·생각 중·말하는 중·마무리)를 받아 T19 그림에 반영하고, 기기 연결이 끊기면 스스로 '연결 끊김·다시 연결 중'으로 바꾼다(DEV-DISPLAY-001). 재생 음성이 마이크로 다시 들어가지 않게 하는 에코 제거는 ADR·PoC 검증 과제다 |
| 하지 않는 것 | GPT Live 직접 연결, 아동 발화 의미·활동 상태 판정 |
| 검증 | 기기 연결을 끊으면 재생이 멈추고 재연결 후 이전 응답이 재생되지 않는다. 보호자 앱의 기능·화면은 기기 형태와 무관하다 |

#### DEV-DISPLAY-001 — 아동 기기 화면 (상태 그림 + 켜기/끄기)

| 항목 | 명세 |
|---|---|
| 화면 | T19 (등록 전은 D0, DEV-REG-001) |
| 요구사항 | FR-E16, NFR-11 |
| 우선순위 | **Must**. 단, 최대한 단순하게 구현 |
| 표시 | 캐릭터 그림(현재 구상: 오리너구리 인형) 하나가 상태에 따라 표정·색을 바꾼다. 상태: **꺼짐**(「켜기」만) / **대기** / **듣는 중** / **생각 중** / **말하는 중** / **마무리**(끝나면 자동으로 대기) / **연결 끊김·다시 연결 중**. 진행 정보·결과·대화 내용(자막)은 표시하지 않는다. 그림 아래에 상태 이름 글자를 둘지는 화면 디자인에서 정한다 |
| 상태 결정 | 아동 서비스가 보내는 표시 상태를 따른다: 활동 없음 → 대기, 아이 발화를 받는 중 → 듣는 중, 판정 턴·응답 생성 중 → 생각 중, 응답 재생 중 → 말하는 중, 마무리 문구 재생 → 마무리 → 대기. 연결 끊김·다시 연결 중은 기기가 스스로 판단한다 |
| 켜기 버튼 | 꺼짐 상태에서 보인다. 마이크·소리 재생 허용을 받고 기기 토큰으로 기기 연결을 시작한다(DEV-CLIENT-001) → 대기. 브라우저가 요구하는 사용자 조작을 이 버튼으로 해결한다 |
| 끄기 버튼 | 켜진 상태에서 보인다. **기기 연결 끊김으로 처리한다** → 꺼짐. 재생을 멈추고 연결을 닫는다. 활동 중이면 아동 서비스는 기기 연결 장애로 보고 VOICE-ERR-001을 따른다: 기술적 일시 정지 → 같은 기기 토큰의 재연결 대기 → 대기시간 안에 다시 켜면 재개 조건에 따라 이어가고, 아니면 기술 문제로 종료 |
| 하지 않는 것 | 다음·건너뛰기·재개 등 진행 조작 버튼, 진행 정보·대화 내용 표시, 아동 입력 화면 |
| 예외 | 마이크·소리 허용 거부 → 연결을 시작하지 않고 꺼짐 유지(보호자 앱의 기기 상태는 '끊김'). 활동이 없을 때 끄기 → 연결만 닫음. 브라우저 데이터 삭제·다른 기기·토큰 무효 → D0(다시 등록) |
| 주체 | 아동 기기, 아동 서비스(표시 상태 전달) |
| 검증 | 꺼짐에서는 그림과 「켜기」만, 켜진 뒤에는 그림과 「끄기」만 보이고 상태에 따라 그림이 바뀐다. 활동 중 끄기를 누르면 12/21에 '잠깐 끊김'이 생기고, 대기시간 안에 켜면 재개되며, 넘기면 기술 문제로 종료(P2)된다 |
| 참고 | 끄기를 기기 연결 끊김으로 처리하므로, 아이가 일부러 끈 경우에도 보호자에게 "대화 중 음성 연결 문제가 발생했어요" 알림이 가고 종료 사유는 '기술 문제'로 남는다 |

#### VOICE-START-001 — 시작 안내·참여 확인

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E01, FR-F02, FR-F20 |
| 우선순위 | Must |
| 주체 | 아동 서비스, GPT Live, 제브(J1) |
| 처리 | 승인 문구로 ① AI와 대화한다는 것 ② 오늘 활동 ③ 기록·보호자 열람 ④ 그만하고 싶을 때 말할 기본 종료 표현 "무중아 그만할래"를 안내하고 참여 의사를 묻는다. 쉬기·건너뛰기·재개는 안내하지 않는다. 아이 응답은 판정 턴으로 J1(참여 / 휴식 요청 / 거부 / 무관·불명확 / 판독 불가)을 판정한다(SYS-JUDGE-001). 참여 → 자유대화(VOICE-FREE-001) 또는 연습(VOICE-PRAC-001). 무관·불명확·판독 불가·판정 보류 → 참여 의사를 다시 확인한다 |

| 검증 | AI 정체와 종료 방법을 안내하고 참여 의사를 처리한다. 추가 종료 표현은 다음 활동부터 반영된다. 휴식 요청이 거부로 처리되지 않는다 |

#### VOICE-DECLINE-001 — 참여 거부 처리

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-E02, FR-F11 |
| 우선순위 | Must |
| 처리 | 참여 질문을 거부했거나, 휴식 요청 없이 답이 없는 경우(VOICE-START-001) 시작 전 미참여로 처리한다. 거부한 경우는 다른 선택지를 1회 제안하고 다시 거부하면 끝낸다. 거부·무응답 모두 승인 마무리 문구를 1회 들려준 뒤 끝낸다. 종료 사유 '시작 전 아동 미참여'로 종료하고 기록은 남기지 않는다 → P3 |

#### VOICE-STOP-001 — 아동 종료 인식 (키워드 + 말의 뜻)

|---|---|
| 요구사항 | FR-E05, FR-A09, FR-E10, FR-F14, FR-F20 |

#### VOICE-END-001 — 마무리

### 5.8 서버·AI·데이터 공통

#### SYS-SESSION-001 — 세션 상태 관리

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-F01 |
| 우선순위 | Must |
| 주체 | 아동 서비스(진행 중), 보호자 서버(통합 저장) |
| 처리 | 실제 활동 상태, 현재 연습 목표·장면 번호·대화 역할·판정 상태 기계의 현재 상태(세션 계획에 고정한 목표 순서), 결과 정리 상태, 연결 대상별 관측 상태를 따로 관리한다(CR-STATE). 대상별 마지막 확인·수신 시각, 이벤트 발생 시각, 종료 확인 여부를 보존한다. 재진입·재연결은 같은 아동·세션의 최신 상태와 확보 이력을 동기화한다. 종료 요청이 남았거나 종료 확인된 세션은 복구로 재개하지 않는다. 미확인 종료 동안 새 세션 시작을 막는다. 종료 표현은 세션 시작 시 설정을 유지한다 |

| 검증 | 앱 종료·앱만 오프라인 시험에서 활동·기록이 유지되고, 뒤늦은 이벤트가 종료 상태를 되돌리지 않는다 |

#### SYS-RELAY-001 — 아동 서비스 → 보호자 서버 상태·기록 전달

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-F01, FR-A06, 공통규칙 '기록 저장 주체'·'서버 간 상태 미수신' |
| 우선순위 | Must |
| 처리 | 아동 서비스가 활동 상태·기록·실시간 전사(SYS-LIVE-001)·진행용 판정 기록(SYS-JUDGE-004)을 보호자 서버에 전달한다. 전달이 중단되면 보관했다가 다시 전달하고, 보호자 서버는 중복 없이 반영한다. 보호자 서버는 미수신 동안 내부 상태 '기기 상태 확인 불가'로 두고 04·05에는 '응답 없음'(회색), 12·21에는 '잠깐 끊김'으로 표시한다(내부에서는 미확인 구간) |
| 예외 | 동의 철회·삭제 이후 도착한 자료는 보호자 서버가 저장하지 않는다. 보관 한계는 ADR |
| 검증 | 전달 중단 후 재개되면 미전달 상태·기록이 중복 없이 반영된다(AC-CON-10) |

#### SYS-LIVE-001 — 실시간 대화 전사 중계

| 항목 | 명세 |
|---|---|
| 화면 | 12, 21 (27의 대화 기록과 같은 전사) |
| 요구사항 | FR-B06, FR-C06, FR-F04, FR-A03 |
| 우선순위 | Must |
| 주체 | 아동 서비스(수신·중계), 보호자 서버(중계·저장), 부모 앱(표시) |
| 처리 | 아동 서비스가 GPT Live의 출력 전사(무중 발화, 예: output_audio_transcript.delta)와 입력 전사(아이 발화, 예: input_audio_transcription.delta/completed)를 받아 화자·시각·확정 여부와 함께 보호자 서버에 보내고, 보호자 서버가 부모 앱에 실시간으로 전달한다. 부모 앱은 진행 중인 발화를 '말하는 중'으로, 확정된 발화를 말풍선으로 보여준다. 확정된 전사는 SYS-TRANS-001로 저장한다. 판정 턴의 '다음 행동 지시'와 제브 판정 결과는 중계하지 않는다 |
| 예외 | 보호자 서버 전달이 끊기면 아동 서비스가 보관했다가 다시 보내고(SYS-RELAY-001) 그 구간은 앱에서 '잠깐 끊김'으로 표시했다가 받은 전사로 채운다. 필수 동의 철회 뒤에는 중계·저장하지 않는다. 시작 전 미참여로 끝난 활동의 전사는 저장하지 않는다. 실시간 전송 방식·지연 목표는 ADR |
| 하지 않는 것 | 원음 중계, 판정 정보 중계, 부모 앱에서 아이에게 말하기 |
| 검증 | 대화 중 무중·아이 발화가 화자·시각과 함께 앱에 나타나고 27 대화 기록과 내용이 같다. 전달 중단 뒤 재전달되면 빠진 발화가 중복 없이 채워진다 |

#### SYS-EVAL-001 — 연습 기록 장면·도움 분리·기록용 재판정

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-F09, FR-F10, FR-F20 |

### 5.9 진행 중 반응 판정 (판정 모델 제브)

#### SYS-JUDGE-001 — 판정 턴 처리 (자동 응답 보류·제브 호출·다음 행동 지시)

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-F20, FR-F15, FR-E07 |
| 우선순위 | Must |
| 주체 | 아동 서비스(상태 기계), GPT Live, 제브 |

| 처리 | ① 판정 턴에서는 아동 서비스가 GPT Live의 자동 응답을 보류한다 ② GPT Live 입력 전사(아이 발화)를 받는다(별도 STT 없음) ③ 제브에 판정 요청(판정 질문·선택지·목표 판정 기준·장면·최근 몇 턴·전사)을 보낸다 ④ 받은 선택지·확률을 확신 문턱으로 확인하고(SYS-JUDGE-002) 상태 기계가 다음 행동(장면 이어 가기·되묻기·집중 연습·상황 다시 설명·다시 말해 달라 확인·종료 등)을 정한다 ⑤ GPT Live에 '다음 행동 지시'를 주입하고 응답을 요청한다. 일반 턴은 GPT Live 자동 응답을 그대로 쓴다. 판정 턴 동안 T19는 '생각 중'을 보여준다(DEV-DISPLAY-001). 판정마다 SYS-JUDGE-004로 기록한다 |

| 검증 | 판정 턴에서 GPT Live가 지시 전에 스스로 응답하지 않는다. GPT Live 요청 로그에 판정 라벨·기준이 없다. 판정 결과마다 정해진 다음 행동이 지시된다 |

| 우선순위 | Must |
| 주체 | 아동 서비스, 보호자 서버(J7), 제브 |
| 처리 | 판정 지점 J1~J7마다 선택지를 미리 정해 두고(CR-JUDGE 표), 제브는 그중 하나를 확률(보정된 신뢰도)과 함께 돌려준다. 1순위 확률이 문턱보다 낮거나 1·2순위 차이가 작으면 **판정 보류**로 보고 교정 없이 되묻는다(J7이면 통과로 보지 않음). 문턱값은 검증 과제다(PoC로 확인하며 팀 결정 항목이 아님). 판정 지점·선택지는 버전과 함께 관리하고 세션 동안 고정한다 |
| 예외 | 선택지에 없는 값은 받지 않는다. 문턱 미달을 '일부 전달'·'여전히 부족' 등 교정이 따르는 선택지로 바꾸지 않는다 |
| 검증 | 모든 판정 지점이 정한 선택지 중 하나 또는 보류만 낸다. 문턱 미달 사례에서 교정·집중 연습이 나오지 않는다 |

#### SYS-JUDGE-003 — 판정 시간 제한·대체 경로

| 항목 | 명세 |
|---|---|
| 요구사항 | FR-F20, FR-F14 |
| 우선순위 | Must |
| 주체 | 아동 서비스 |
| 처리 | 전사가 제한 시간 안에 오지 않으면 판독 불가로 처리하고 "다시 말해 줄래?"처럼 확인한다. 제브가 제한 시간 안에 응답하지 않으면 판정 보류로 보고 무난한 되묻기를 지시한다. 응답 공백 허용 시간(아이 말이 끝난 뒤 무중이 응답하기까지 허용하는 최대 공백)은 10초(임시값, ADR에서 바꿀 수 있음)다. 10초 안에 응답이 준비되지 않으면(예: 전사나 제브 판정이 늦음) 판정 보류로 처리하고 무난한 되묻기나 맞장구로 응답한다. 전사·제브 제한 시간은 이 10초 상한 안에서 ADR로 정한다(후보: 전사 1.5초, 제브 800ms). 제한 시간이 지난 뒤 도착한 전사·판정은 진행에 쓰지 않고 판정 기록에만 남긴다 |
| 예외 | 제브 응답 지연·실패는 음성 대화 장애가 아니며 활동을 멈추지 않는다. 대체 경로에서도 교정·표현 예시를 주지 않는다 |
| 검증 | 전사 지연·제브 지연을 각각 주입하면 판독 불가 확인·무난한 되묻기로 이어지고 교정이 나오지 않는다. 전사·판정이 모두 늦어도 아이 말이 끝난 뒤 10초 안에 되묻기나 맞장구가 나온다. 늦게 온 판정이 다음 행동을 바꾸지 않는다 |

| 항목 | 명세 |
