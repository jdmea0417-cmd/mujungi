## 0. 읽는 법

1. **요구사항 하나 = 카드 하나.** 카드는 **트리거 · 선행 조건 · 입력 · 처리 · 출력 · 예외·분기 · 하지 않는 것 · 완료 기준** 순서다. 그 아래에 원본 문장을 그대로 붙였다(**원문**). 카드와 원문이 다르게 읽히면 원문을 따른다.
2. **완료 기준**은 원본 엑셀에 칸이 없어서, 이 요구사항에 연결된 기능명세서 v1.3 기능의 '검증' 칸을 기능 ID와 함께 옮겼다. 수용 테스트의 기준으로 쓴다.
3. **ID는 추적 키다.** 요구사항(FR·NFR), 화면(01~29 · P · SET · D0 · T19), 산출물(DATA-), 이벤트(EV-), 판정 지점(J1~J7), 기능 ID를 설계·코드·테스트에서 그대로 쓴다. DATA·EV ID는 이 문서에서 붙였다.
4. **화살표:** `⇒ DATA-xx`는 그 산출물을 만든다는 뜻, `→ 화면/요구사항`은 그쪽으로 이어진다는 뜻이다.
5. **화면 번호는 화면 설계 v1.6을 따른다.** 자유대화·연습은 진행 화면 12와 끝 화면 17을 함께 쓴다(원문의 21 연습 진행 = 12, 23 연습 끝 = 17).
6. **'하지 않는 것'은 구현 금지 사항이다.** 카드에 없는 기능을 덧붙이지 않는다.
7. **값을 지어내지 않는다.** 시간·횟수·문턱값 등 원문이 ADR로 넘긴 값은 기술명세서 §13(값 목록)·§14(미결)를 따르고, 거기에도 없으면 질문한다. 임시값(목표당 10분, 응답 공백 10초 등)은 바꿀 수 있는 값이다.
8. **우선순위:** Must는 줄이지 않는다. Should는 단순화·연기할 수 있다. Could는 여유가 있을 때 한다.

## 1. 시스템 경계

### 1.1 행위자와 구성 요소

| 행위자·구성 요소 | 접점 | 하는 일 |
|---|---|---|
| 보호자 | 보호자 앱(01~29 · 팝업 · 시트) | 구글 로그인, 동의, 아이 등록, 기기 등록, 활동 시작·종료, 기록·리포트 확인, 목표 담기·선택 |
| 아동(6~12세) | 아이 기기 웹(D0 · T19) | 「켜기」/「끄기」, 음성으로만 참여·대화·연습, 종료 의도 표현 |
| 보호자 서버 | 보호자 앱 ↔ 보호자 서버 | 계정·동의·아동·기기 등록, 활동 배정, 상태·기록 저장, 기록 정리·리포트 |
| 아동 서비스 | 아이 기기 ↔ 아동 서비스 ↔ GPT Live | 기기 연결 하나 유지, 음성 중계, 활동 진행 상태, 판정 차례 처리, 장애·복구·종료 확인 |
| GPT Live | 아동 서비스와 서버끼리 연결 | 실시간 음성 대화(친구·코치 역할), 실시간 도움, 입력·출력 전사 |
| 판정 모델 제브(Jev) | 아동 서비스 → 제브 | 진행 중 판정(J1~J7): 텍스트 → 선택지 + 확률 |
| 분석 AI | 보호자 서버 → 분석 AI | 활동 전·후: 장면 대본, 경험 구조화, 목표 후보, 기록용 재판정, 결과 문장, 생활 팁, 리포트 문장 |
| 전문가 | 없음(시스템 밖) | 보호자가 직접 건넨 PDF를 본다 |

규칙

- 종료 확인·취소는 되돌아가지 않는다. 늦거나 중복된 사건은 기록만 하고 상태를 바꾸지 않는다.
- 종료 요청이 있거나 종료가 확인된 활동은 복구만으로 다시 이어 가지 않는다.
- 진행 중이거나 종료가 확인되지 않은 활동은 계정마다 하나다. 그동안 새 활동을 시작할 수 없다.
- 대상 아이, 종료 표현, 승인 문구 버전, 연습 계획(목표·순서)은 시작 때 고정한다.
- 보호자 앱 접속 여부는 활동 상태가 아니다.

### 4.1 연습 진행 (목표마다, 원문 FR-E06~E09 · F20)

```
장면 시작(정답 표현 없음) → 기회 문장 → 첫 반응(J2)
  ├ 목표에 맞게 전달 ──────────────→ 교정 없이 이어 감 → 장면 정리
  ├ 일부 전달 → 상대 역할로 1회 되묻기(J3) ─┬ 전달 → 이어 감 → 장면 정리
  │                                         └ 여전히 부족 → 도움 제안(J4)
  ├ 도움 요청 · 지원 필요 → 집중 연습(코치 역할) → 다시 해 보기(J5) → 친구 역할 복귀 → 장면 정리
  ├ 상황 이해 못함 · 무관한 말 → 상황 설명을 쉽게 바꿔 다시 제시
  └ 판독 불가 · 확신 낮음 → 판정 보류, "다시 말해 줄래?"
도움 제안(J4): 수락 → 집중 연습 / 거절 → 원래 장면 이어 가기 또는 정리
장면 정리 → (시간·참여 의사 남음, 목표 10분 전) 변형 장면 → 같은 흐름
          → 아니면 다음 목표 → … → 마지막에 한 번 마무리
```

도움이나 변형 장면을 반드시 거치는 고정 단계 구조가 아니다. 생략한 단계는 미실시 실패가 아니다.

## 8. 보호자 앱 · 계정 (FR-A)

### FR-A01 로그인 (구글)

`Must` · 주체: 보호자 앱 · 화면: 01 로그인

- **트리거:** 보호자가 01에서 「구글로 시작」을 누른다 / 앱에 다시 들어온다 / 로그아웃한다
- **선행 조건:** 없음
- **입력:**
  - 구글 인증 결과(성공·취소·실패)
  - 로그인 상태(재접속 시)
  - DATA-03 동의 여부, DATA-02 아이 등록 여부(분기용)
- **처리:**
  1. 구글 인증으로 보호자를 확인하고, 처음이면 보호자 계정을 만든다
  2. 로그인 상태가 유효하면 재접속 때 로그인을 다시 묻지 않는다
  3. 첫 로그인 뒤 02 → 03(첫 등록) → 04 순서로 보낸다. 아이가 등록돼 있으면 바로 04
- **출력:**
  - ⇒ DATA-01 보호자 계정 · 로그인 상태
  - 화면 이동: 02 / 03 / 04
- **예외·분기:**
  - 취소·실패 → 로그인되지 않은 상태로 01에 남고 다시 시도할 수 있다
  - 로그아웃 → 01
- **하지 않는 것:**
  - 자체 회원가입·아이디/비밀번호 로그인
  - 카카오·네이버 로그인
  - 아동용·전문가용 로그인
  - 다른 계정 데이터 접근
- **완료 기준 (기능명세서 검증):**
  - AUTH-S01-001: 01에는 「구글로 시작」만 있고 자체 가입·ID/PW 입력·다른 제공자가 없다. 취소·실패를 로그인 완료로 표시하지 않는다
  - AUTH-S01-002: 첫 인증 후 별도 가입 없이 계정과 로그인 상태가 생기고 02 → 03 → 04 순서로 간다. 아동을 등록한 뒤에는 로그인하면 바로 04로 간다. 인증 성공 후 해당 보호자 데이터에만 접근한다
  - AUTH-S01-003: 유효한 로그인 상태에서 재접속 시 다시 로그인하지 않는다
  - AUTH-S01-004: 로그아웃 후 보호 화면에 접근할 수 없고, 진행 중 활동은 종료되지 않는다
- **상세 기능:** AUTH-S01-001, AUTH-S01-002, AUTH-S01-003, AUTH-S01-004

**원문**

> - 보호자는 구글 계정으로만 로그인하고, 서비스에서 로그아웃할 수 있다.
> - 자체 회원가입·아이디/비밀번호 로그인, 카카오·네이버 로그인, 아동용·전문가용 로그인은 두지 않는다.
> - 로그인 상태가 유지되면 다시 접속할 때 로그인을 다시 묻지 않는다.
> - 로그인을 취소하거나 실패하면 로그인되지 않은 상태로 남고, 다시 시도할 수 있다.
> - 첫 로그인 뒤에는 기록·동의 안내 → 내 아이(첫 등록) → 홈 순서로 진행한다.
>   - 아이를 등록한 뒤에는 로그인하면 바로 홈으로 간다.
> - 로그인한 보호자는 자기 계정의 데이터에만 접근할 수 있다.

  - ⇒ DATA-06 종료 표현 설정 → 다음 활동의 종료 인식(FR-E05)
  - 저장 완료 / 저장 실패 구분 표시
- **예외·분기:**
  - 빈 값·중복 → 저장되지 않음
  - 「취소」 → 저장하지 않은 변경을 버림
  - 진행 중 활동 → 바뀌지 않음
- **하지 않는 것:**
  - 기본 종료 표현 변경·삭제
  - 종료 표현을 종료의 유일한 방법으로 두기
- **완료 기준 (기능명세서 검증):**
  - DEV-S05-001: 기기 연결 장애·음성 모델 연결 장애·부모 앱 연결 장애·상태 미수신을 각각 주입하면 대상과 확인 수준이 구분돼 표시된다. 부모 앱만 오프라인이면 활동·기록은 지속되고 앱에 마지막 확인 시각·상태가 보인다. 등록 전에는 기기 등록 줄이 '없음'이고 「+ 기기 등록」이 보인다(04는 '연결된 기기 없음')
  - STOP-SET01-002: 빈 값과 중복은 저장되지 않는다. 기본 표현은 편집·삭제할 수 없다
  - STOP-SET01-003: 저장 완료·실패가 구분되고 저장한 표현이 다음 활동부터 반영된다
  - VOICE-STOP-001: 키워드는 확인 질문 없이 종료된다. 키워드가 아닌 명확한 종료 의도도 처리된다. 대사·재생 음성·주제 거부·휴식 요청으로 종료되지 않는다. 종료 확정 후 이전 응답이 재생되지 않는다
- **상세 기능:** DEV-S05-001, STOP-SET01-001, STOP-SET01-002, STOP-SET01-003, STOP-SET01-004, VOICE-STOP-001

**원문**

> - 보호자는 우리 집 기기 화면의 종료 표현 「설정」에서 아이의 종료 표현을 관리한다.
> - 기본 종료 표현 “무중아 그만할래”는 항상 남고, 바꾸거나 지울 수 없다.
> - 보호자는 아이의 추가 종료 표현을 등록·편집·삭제하고 저장하거나 취소할 수 있다.
>   - 빈 값·중복은 저장되지 않고, 취소하면 저장하지 않은 변경을 버린다.
> - 저장한 표현은 다음 자유대화·연습부터 적용하고, 진행 중인 활동에는 바꾸지 않는다.
> - 아이가 등록한 표현을 말하면 확인 없이 종료하지만, 종료할 수 있는 유일한 방법은 아니다.
> - 저장 완료와 저장 실패를 구분해 보여 준다.

### FR-A10 활동 장애·상태 미확인 푸시 알림

`Must` · 주체: 서버 · 화면: 04 홈, 12 활동 진행, P1 끝내기 팝업, P2 예상치 못한 종료 팝업, 17 활동 끝, 27 활동 기록 상세

- **트리거:** 서버가 음성 대화 장애 · 기기 상태 수신 중단 · 기술 문제 종료 확인을 감지
- **선행 조건:** 보호자 계정에 푸시 대상 등록
- **입력:**
  - 장애·상태 미확인·종료 확인 사건
  - 세션 ID와 상태
- **처리:**
  1. 보호자 앱 실행 여부와 상관없이 푸시 발송을 요청한다
  2. 상황별 문구를 쓴다: 음성 대화 장애 "대화 중 음성 연결 문제가 발생했어요." / 기기 상태 미확인 "기기 상태를 확인할 수 없어요." / 기술 문제 종료 확인 "연결 문제로 활동이 종료됐어요."
  3. 같은 사건은 한 번만 보낸다
- **출력:**
  - ⇒ DATA-26 푸시 알림
  - 알림 누름·재진입 → 최신 상태 조회 → 12 또는 17(기술 문제 종료는 P2 → 17)
- **예외·분기:**
  - 앱을 닫음·보호자 앱 연결만 문제 → 기기 장애·종료 알림을 만들지 않음
  - 조회 실패 → 마지막 확인 시각 + 미확인 표시. 오래된 알림 문구로 현재 상태를 덮어쓰지 않음
  - 발송 요청과 실제 전달을 구분한다. 즉시 전달은 보장하지 않는다
- **하지 않는 것:**
  - 알림에 대화 내용·발화 원문 넣기
  - 같은 사건 중복 발송
- **완료 기준 (기능명세서 검증):**
  - HOME-S04-001: 홈에서 03·05·SET-00으로 진입한다. 재진입 시 진행·기술적 일시 정지·종료 확인 상태가 반영되고 조회 실패 시 마지막 확인 시각이 유지된다
  - NOTI-PUSH-001: 앱을 닫고 세 사건을 각각 일으키면 올바른 문구·아동·세션으로 발송 요청이 남는다. 종료 확인이 없으면 종료 알림이 없다
  - NOTI-PUSH-002: 복구 후 과거 장애 알림을 선택하면 최신 상태로 이동한다
  - ACT-S12-001: 대화 중 무중·아이 발화가 시각과 함께 순서대로 보인다. 음성 대화 장애를 주입하면 '잠깐 끊김' 구간 하나가 생기고, 앱만 오프라인이던 동안 계속된 대화는 재조회 후 실제 전사로 이어진다. 상태 미수신 구간은 재전달 후 실제 기록으로 바뀐다. 종료 확인 후에만 17(기술 문제 종료는 P2 안내 후)로 바뀐다
  - ACT-P2-001: 기술 문제 종료만 P2를 거치고 아동 중단·공백 자동 종료는 P2 없이 17·23으로 간다. 같은 세션의 27 종료 사유와 푸시 알림이 일치한다. 장애·미확인을 아동 종료 의도나 실패로 추정하지 않고, 보호자 서버의 기록 미수신을 아동 거부나 대화 없음으로 바꾸지 않는다
  - PRAC-S21-001: 상단에 시작 시각·n분째만 있고 단계·목표 번호가 없다. 연습 대화가 시각과 함께 순서대로 보인다. 음성 대화 장애와 상태 미수신 구간이 모두 '잠깐 끊김'으로 표시되고 기록에서는 구분된다. 기술 종료 확인 후 P2 → 23으로 연결되며 장면 미실시를 실패로 처리하지 않는다
  - HIST-S27-003: 준비 중·생성 실패·자료 부족이 구분되고 종료 확인과 기록 정리·확보 범위가 구분된다. 같은 세션의 종료 사유가 P2·푸시 알림과 일치한다
  - VOICE-ERR-001: 네 가지 장애를 각각 주입하면 공통규칙 AC-CON-01~10대로 표시·처리된다(12·21은 '잠깐 끊김', 04·05는 대상별 표시, T19는 '연결 끊김·다시 연결 중', 기술 종료는 P2)
- **상세 기능:** HOME-S04-001, NOTI-PUSH-001, NOTI-PUSH-002, ACT-S12-001, ACT-P2-001, PRAC-S21-001, HIST-S27-003, VOICE-ERR-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 감지·알림 발생 기준, 지연·중복 억제 정책, 전달 상태 확보 범위
  - 참고: 공백 자동 종료 알림도 종료 확인(FR-F18·B07)을 따름

**원문**

> - 서버가 음성 대화 장애나 기기 상태 수신 중단을 감지하면, 보호자 앱 실행 여부와 상관없이 푸시 발송을 요청한다.
> - 알림 문구는 상황별로 구분한다.
>   - 음성 대화 장애: “대화 중 음성 연결 문제가 발생했어요.” / 기기 상태 미확인: “기기 상태를 확인할 수 없어요.” / 기술 문제로 종료까지 확인됨: “연결 문제로 활동이 종료됐어요.”
> - 앱을 닫았거나 보호자 앱 연결만 문제인 경우에는 기기 장애·종료 알림을 만들지 않는다.
> - 같은 사건은 한 번만 보내고, 대화 내용·발화 원문은 넣지 않는다.
> - 발송 요청과 실제 전달을 구분하며, 휴대폰 통신·알림 설정에 따라 즉시 전달을 보장하지 않는다.
> - 알림을 누르거나 앱에 다시 들어오면 최신 상태를 조회해 진행 화면 또는 종료 화면(기술 문제 종료는 P2 안내 뒤)으로 연결한다.
>   - 조회에 실패하면 마지막 확인 시각과 미확인을 보여 주고, 오래된 알림 문구로 현재 상태를 덮어쓰지 않는다.

### FR-A11 아동 기기 등록

`Must` · 주체: 보호자 앱 · 화면: 05 우리 집 기기, 05a 기기 등록, D0 아이 기기 처음 켜기

- **트리거:** 아이 기기를 처음 켬(D0) / 보호자가 05 → 05a에서 코드 입력
- **선행 조건:** DATA-01 로그인
- **입력:**
  - 아이 기기 화면의 고정 등록 코드
  - 보호자가 입력한 코드
- **처리:**
  1. 아이 기기를 처음 켜면 등록 코드를 보여 준다
  2. 코드가 맞으면 기기를 보호자 계정에 등록하고 기기 토큰을 발급한다
  3. 등록 뒤 기기는 코드 없이 자동 연결되고 대기 화면으로 바뀐다
- **출력:**
  - ⇒ DATA-04 기기 등록·기기 토큰
  - 05 기기 등록 완료, D0 → T19 대기
- **예외·분기:**
  - 없는 코드·다른 계정에 등록된 기기 → 등록하지 않고 이유 표시
  - 등록 전 → 04 '연결된 기기 없음', 자유대화·연습 시작 불가
  - 기기 저장 정보 삭제·다른 기기 → 다시 등록. 새 기기 등록 시 이전 등록·기기 토큰 무효
- **하지 않는 것:**
  - 계정당 기기 두 대 이상
- **완료 기준 (기능명세서 검증):**
  - DEV-S05-001: 기기 연결 장애·음성 모델 연결 장애·부모 앱 연결 장애·상태 미수신을 각각 주입하면 대상과 확인 수준이 구분돼 표시된다. 부모 앱만 오프라인이면 활동·기록은 지속되고 앱에 마지막 확인 시각·상태가 보인다. 등록 전에는 기기 등록 줄이 '없음'이고 「+ 기기 등록」이 보인다(04는 '연결된 기기 없음')
  - DEV-S05A-001: 올바른 코드를 넣으면 기기가 이 계정에 묶이고 다음부터 코드 없이 연결된다. 없는 코드·다른 계정 기기는 등록되지 않고 이유가 보인다
  - DEV-REG-001: 등록 전에는 코드가 보이고, 등록 후에는 코드 없이 연결되며 T19로 바뀐다
  - DEV-TOKEN-001: 등록되지 않았거나 토큰이 유효하지 않은 기기는 활동에 참여할 수 없다. 다른 계정의 활동에 참여할 수 없다
  - DEV-CLIENT-001: 기기 연결을 끊으면 재생이 멈추고 재연결 후 이전 응답이 재생되지 않는다. 보호자 앱의 기능·화면은 기기 형태와 무관하다
- **상세 기능:** DEV-S05-001, DEV-S05A-001, DEV-REG-001, DEV-TOKEN-001, DEV-CLIENT-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 코드 형식, 기기 토큰 만료·재발급, 등록 해제

**원문**

> - 아이 기기를 처음 켜면 고정 등록 코드를 보여 준다.
> - 보호자는 우리 집 기기 → 「+ 기기 등록」에서 이 코드를 입력해 기기를 보호자 계정에 등록한다.
> - 계정마다 아이 기기는 한 대이며, 그 계정의 아이가 쓴다.
> - 등록되면 기기는 다음부터 코드 없이 자동으로 연결되고 대기 화면으로 바뀐다.
> - 없는 코드이거나 이미 다른 계정에 등록된 기기는 등록하지 않고 이유를 보여 준다.
> - 등록 전에는 홈의 기기 상태가 ‘연결된 기기 없음’이고 자유대화·연습을 시작할 수 없다.
> - 기기의 저장 정보가 지워지거나 다른 기기를 쓰면 다시 등록한다.
>   - 새 기기를 등록하면 이전 기기 등록과 기기 토큰은 무효가 된다.

**원문**

> - 진행 중이거나 종료 확인이 안 된 활동이 있는 아이는 삭제하지 않고 이유를 보여 준다.
> - 삭제하면 내 아이의 첫 등록(빈 카드)으로 간다.
>   - 동의와 아이 기기 등록은 계정에 남는다.
> - 삭제한 아이는 홈·연습 목표·리포트 범위에 나오지 않으며, 삭제 실패를 성공으로 보여 주지 않는다.

### FR-A13 계정 삭제

  - HOME-SET00-002: 삭제 뒤 같은 구글 계정으로 로그인하면 이전 아동·기록이 없고 02부터 시작한다. 등록했던 아이 기기는 그 계정의 활동에 참여할 수 없다. 진행 중 활동은 종료 확인 뒤에만 삭제된다

**원문**

>   - 대상: 계정, 아이, 기록·리포트·연습 목표, 계정에 묶인 기기 등록
> - 확인 단계에서 취소하면 아무것도 바뀌지 않는다.

### FR-B06 자유대화 진행 상태 확인

> - 맨 위에 상태 한 줄(예: “무중이 민준에게 말을 걸고 있어요”)과 시작 시각·경과 분(예: “10:31 시작 · 4분째”)을 보여 준다.
> - 그 아래에 실시간 대화 글을 말풍선(무중·아이 발화와 시각)으로 보여 주고, 말하고 있는 발화는 ‘말하는 중’으로 표시한다.
> - 상태 한 줄로 참여 기다리는 중 / 대화 중 / 끝내는 중을 구분하고, 판정 결과·확률·점수는 보여 주지 않는다.
> - 대화 중 연결 문제(기술적 일시 정지, 보호자 서버의 상태 미수신)는 대화 흐름에 ‘잠깐 끊김’ 구간 하나로 보여 준다.
>   - 어느 연결의 문제인지는 홈·우리 집 기기에서 구분하고, 기록에서는 기술적 일시 정지와 상태 미확인을 따로 남긴다.
> - 보호자 앱 연결만 문제면 “실시간 상태를 불러오지 못하고 있어요”와 마지막 확인 시각을 보여 주고, 그 시간을 끊김으로 채우지 않는다.
>   - 다시 연결되면 실제로 받은 대화 글로만 채우고, 받지 못한 구간은 미확인으로 남긴다.
> - 아이의 침묵·마이크 문제·AI 응답 지연은 연결 문제로 보여 주지 않고, 4분 공백도 따로 표시하지 않는다.
> - 쉬기 기능, 보호자 마이크, 다음 질문 버튼은 두지 않으며, 아이가 쉬고 싶다고 하면 기록만 하고 대화를 이어 간다.

### FR-B07 보호자 종료

`Must` · 주체: 보호자 앱 · 화면: 12 활동 진행, P1 끝내기 팝업

- **트리거:** 12 「끝내기」 → P1 확인(시작 안내 중 포함)
- **선행 조건:** DATA-08 진행 중 활동
- **입력:**
  - P1 응답
  - 아동 서비스의 종료 수신·기기 종료 확인
- **처리:**
  1. 종료 요청을 보내고 상태를 "전송하지 못함" / "끝내는 중"(서버에 종료 요청됨) / "기기 종료 확인됨"으로 구분해 보여 준다
  2. 다시 연결되면 현재 활동을 먼저 조회한다
- **출력:**
  - 기기 종료 확인 → 17(기술 문제 종료는 P2 → 17)
  - ⇒ DATA-22 종료 사유 '보호자 중단'
- **예외·분기:**
  - 기기 확인이 오지 않음 → "종료 확인 안 됨" + 마지막 확인 시각 + 원격 제어의 한계
  - 보호자 앱만 오프라인 → 보낼 수 없다고 알리고 '종료 요청됨'으로 표시하지 않음
  - 종료가 불분명한 동안 → 새 활동 시작 불가
  - 중복 요청·이전 명령 → 다른 활동에 적용하지 않음
  - 자동 종료도 기기 종료 확인 뒤에만 17과 완료 알림
- **하지 않는 것:**
  - 종료를 기록 삭제로 처리
  - 요청 접수나 시간 경과만으로 종료 완료 처리
  - 앱 닫기를 종료 요청으로 처리
- **완료 기준 (기능명세서 검증):**
  - ACT-S12-002: 종료 처리 중에 종료 완료로 표시되지 않고 새 활동이 시작되지 않는다
  - ACT-P1-001: 정상 경로에서 종료 요청을 받으면 출력이 멈추고 종료 확인 후 완료된다. 재시도·중복 응답으로 다른 세션이 종료되지 않는다
  - ACT-P1-002: 확인 대기 중 종료 완료·새 활동 시작이 허용되지 않는다. 늦게 온 확인이 이전 상태로 되돌리지 않는다
- **상세 기능:** ACT-S12-002, ACT-P1-001, ACT-P1-002
- **넘긴 결정·참고:**
  - 화면 설계 참고: ‘전송하지 못함’·‘종료 확인 안 됨’ 상태 그림 없음(명세대로 표시)
  - 참고: 통신 장애 중 원격 즉시 종료는 보장하지 않음 / 앱을 닫는 것은 종료 요청이 아님

**원문**

> - 보호자는 진행 화면의 「끝내기」 → 확인 팝업으로 종료를 요청할 수 있다(시작 안내 중 포함).
> - 종료와 기록 삭제는 별개다.
> - 종료 상태를 “전송하지 못함” / “끝내는 중”(서버에 종료 요청됨) / “기기 종료 확인됨”으로 구분해 보여 준다.
>   - 기기 확인이 오지 않으면 “종료 확인 안 됨”과 마지막 확인 시각, 원격 제어의 한계를 보여 준다.
> - 보호자 앱만 오프라인이면 요청을 보낼 수 없다고 알리고, ‘종료 요청됨’으로 보여 주지 않는다.
> - 요청 접수나 시간 경과만으로 종료 완료로 보지 않으며, 종료가 불분명한 동안 새 활동을 시작하지 않는다.
> - 다시 연결되면 현재 활동을 먼저 조회하고, 중복 요청이나 이전 명령이 다른 활동에 적용되지 않게 한다.
> - 자동 종료도 기기 종료 확인 뒤에만 종료 화면(기술 문제 종료는 P2 뒤)과 완료 알림으로 넘어간다.

  - 지원 조건(FR-F19)을 갖추지 않은 목표를 고를 수 있게 하기
- **완료 기준 (기능명세서 검증):**

  - SYS-GOAL-001: 담을 수 있는 모든 목표가 상황 생성부터 결과 생성까지 동작한다. 담기·즐겨찾기·삭제가 저장되고 연습 뒤 연습 횟수·지난 연습 기록이 갱신된다. 목표에 연령 정보가 없다
- **상세 기능:** PRAC-S18-002, ACT-S18-001, PRAC-S21-001, PRAC-NEXT-001, SYS-GOAL-001
- **넘긴 결정·참고:**

**원문**

> - 목표마다 상황 대화(장면)를 진행하고, 장면을 정리하면 다음 목표로 넘어가며, 마지막에 한 번 마무리한다.

> - 담기·선택만으로는 기기가 움직이지 않고, 시작 버튼을 눌러야 시작한다. 고르지 않고 나갈 수도 있다.

### FR-C05 연습 시작 요청

`Must` · 주체: 보호자 앱 · 화면: 18 내 연습 목표, 12 활동 진행

- **트리거:** 18 「연습 시작」
- **선행 조건:** 시작 조건(기기 연결 준비·필수 동의·이전 활동 종료 확인) — 홈 탭 잠금으로 먼저 확인
- **입력:**
  - DATA-17 연습 계획
  - DATA-02 대상 아이
- **처리:**
  1. 요청할 때 시작 조건을 한 번 더 확인한다
  2. 서버가 받아들이면 상황을 만든다(FR-F07)
  3. 같은 요청이 두 번 들어가지 않게 한다
- **출력:**
  - ⇒ DATA-08 활동 세션(연습)
  - 12 연습: 상황 준비 중 → 시작 요청됨·기기 실행 확인 중 → 기기 안내 확인 → 연습 안내
- **예외·분기:**
  - 보호자 앱 연결 문제·기기 연결 준비 미확인·이전 활동 종료 미확인 → 시작하지 않음
  - 상황 만들기 실패 → 시작하지 않고 18에서 이유 안내(FR-F07)
- **하지 않는 것:**
  - 별도 준비 화면
  - 연습 상황 본문을 보호자에게 미리 보여 주기
- **완료 기준 (기능명세서 검증):**
  - HOME-S04-002: 조건 중 하나라도 미충족이면 자유대화·연습을 시작할 수 없고 이유가 안내된다. 등록된 기기가 기기 토큰으로 연결된 경우만 준비 완료다
  - ACT-START-001: 서버 수락과 기기 안내 실행이 구분돼 표시된다
  - ACT-S18-001: 서버 수락을 기기 실행 확인으로 표시하지 않고 중복 없이 시작한다. 생성·점검 실패를 정상 생성으로 표시하지 않는다. 고른 목표와 순서가 세션 계획에 고정된다. 상황 준비 중 취소 뒤 기기는 아무것도 받지 않는다
- **상세 기능:** HOME-S04-002, ACT-START-001, ACT-S18-001
- **넘긴 결정·참고:**
  - 참고: 중복 제출 방지는 공통규칙 ‘활동 시작 조건’ 참조

**원문**

> - 내 연습 목표에서 고른 목표로 「연습 시작」을 누르면 시작을 요청한다(별도 준비 화면 없음).
> - 연습 상황 본문은 보호자에게 미리 보여 주지 않는다.
> - 시작 조건(기기 연결 준비·필수 동의·이전 활동 종료 확인)은 홈의 탭 잠금으로 먼저 확인하고, 요청할 때 한 번 더 확인한다.
>   - 보호자 앱 연결 문제, 기기 연결 준비 미확인, 이전 활동 종료 미확인이면 시작하지 않는다.
> - 서버가 받아들이면 연습 진행 화면에서 상황 준비 중과 시작 요청·기기 실행 확인 상태를 구분해 보여 준다.
>   - 기기 안내가 실제로 확인되면 연습 안내로 이어진다.
> - 같은 요청이 두 번 들어가지 않게 한다.
> - 상황 만들기에 실패하면 시작하지 않고, 내 연습 목표 화면에서 이유를 안내한다(FR-F07).

> - 연습이 정상 종료되면 연습 끝 화면에서 종료 사실과 기록 정리 상태(정리 중·정리 끝·정리 실패)를 구분해 안내한다.

> - 정리가 끝나면 「오늘 연습 기록 보기」가 켜지고, 누르면 그 활동의 기록 상세로 간다. 홈으로도 돌아갈 수 있다.
>   - 정리가 끝나도 기록 상세로 자동 이동하지 않는다.
> - 정리 중 상태가 활동 진행으로 보이지 않게 하고, 종료 버튼은 두지 않는다.

### FR-C08 연습 부분 종료 안내

`Should` · 주체: 보호자 앱 · 화면: P2 예상치 못한 종료 팝업, 17 활동 끝, 27 활동 기록 상세

- **트리거:** 연습이 정상 마무리가 아닌 이유로 끝남
- **선행 조건:** DATA-08 활동 세션(연습)
- **입력:**
  - DATA-22 종료 사유·종료 확인·확보 범위
  - DATA-20 목표별 장면 기록 여부
- **처리:**
  1. 기술 문제로 기기 종료 확인 → P2 → 「확인」 → 17
  2. 아이 중단·보호자 종료(P1)·공백 자동 종료 → 팝업 없이 종료 확인 뒤 17
- **출력:**
  - 17: 정리 상태만
  - 27: 종료 사유·목표별 장면 기록 여부·확보된 기록·미확인 구간
  - 같은 활동의 팝업·17·27·알림 내용이 서로 일치
- **예외·분기:**
  - 종료 요청만 접수되고 기기 확인 없음 → 12 '끝내는 중'에서 종료 요청됨·확인 안 됨. 완료로 바꾸지 않음
- **하지 않는 것:**
  - 장애·상태 미확인·공백을 아이의 종료 의도나 미실시 실패로 추정
  - 앱 연결 문제를 종료 사유로 쓰기
- **완료 기준 (기능명세서 검증):**
  - ACT-P2-001: 기술 문제 종료만 P2를 거치고 아동 중단·공백 자동 종료는 P2 없이 17·23으로 간다. 같은 세션의 27 종료 사유와 푸시 알림이 일치한다. 장애·미확인을 아동 종료 의도나 실패로 추정하지 않고, 보호자 서버의 기록 미수신을 아동 거부나 대화 없음으로 바꾸지 않는다
- **상세 기능:** ACT-P2-001
- **넘긴 결정·참고:**
  - 참고: 공백 종료 사유는 FR-F18

**원문**

> - 연습 중 기술 문제로 기기 종료가 확인되면 예상치 못한 종료 팝업(P2)으로 알리고, 「확인」하면 연습 끝 화면으로 간다.
> - 아이 중단, 보호자 종료(끝내기 팝업), 공백 자동 종료는 팝업 없이, 종료 확인 뒤 바로 연습 끝 화면으로 간다.
> - 연습 끝 화면은 정리 상태만 보여 주고, 종료 사유·목표별 장면 기록 여부·확보된 기록·미확인 구간은 기록 상세에서 보여 준다.
> - 종료 요청만 접수되고 기기 확인이 없으면 ‘끝내는 중’ 상태에서 종료 요청됨·확인 안 됨을 보여 주고, 완료로 바꾸지 않는다.
> - 종료가 확인되면 같은 활동의 팝업·연습 끝·기록 상세·알림 내용이 서로 일치한다.
> - 장애·상태 미확인·공백을 아이의 종료 의도나 미실시 실패로 추정하지 않고, 앱 연결 문제를 종료 사유로 쓰지 않는다.

**원문**

## 12. 아이 기기 (FR-E)

### FR-E01 시작 안내와 참여 확인

> - 쉬기·건너뛰기·재개 명령은 안내하지 않는다.

### FR-E02 참여 거부 처리

`Must` · 주체: 아이 기기 · 화면: P3 아이 무응답 팝업

- **트리거:** 시작 안내의 참여 질문에 거부·무응답
- **선행 조건:** 안내·참여 확인 단계
- **입력:**
  - 아이 응답(J1 판정)
  - 휴식 요청 여부
  - 연결 상태
- **처리:**
  1. 거부하면 다른 선택지를 1회 제안하고, 다시 거부하면 마무리한다
  2. 거부하거나 쉬고 싶다는 말 없이 답이 없으면 시작 전 미참여로 본다
- **출력:**
  - 시작 전 미참여 → P3, 기록 없음(FR-F11)
- **예외·분기:**
  - "쉬고 싶어" → 거부가 아니라 휴식 요청으로 기록하고 시작 안내를 이어 감
  - 특정 주제만 거부 → 다른 주제 제안, 종료 아님
  - 연결 장애·기술적 일시 정지로 답을 확인할 수 없는 시간 → 무응답으로 세지 않음
  - 판독 불가·불명확 → 거부로 보지 않음
- **하지 않는 것:**
  - 무응답·휴식 요청을 아동 중단으로 기록
  - 재권유 2회 이상
- **완료 기준 (기능명세서 검증):**
  - ACT-P3-001: 미참여로 끝나면 P3만 보이고 26·27에 기록이 남지 않으며 전사·판정 기록이 저장되지 않는다
  - VOICE-DECLINE-001: 재권유가 1회를 넘지 않는다
- **상세 기능:** ACT-P3-001, VOICE-DECLINE-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 무응답 대기 시간
  - 참고: 진행 중 종료 의도는 FR-E05

**원문**

> - 시작 안내의 참여 질문을 거부하거나, 쉬고 싶다는 말 없이 답이 없으면 시작 전 미참여로 본다.
> - 거부하면 다른 선택지를 1회 제안하고, 다시 거부하면 마무리한다.
> - “쉬고 싶어”는 거부가 아니라 휴식 요청으로 기록하고, 시작 안내를 이어 간다.
> - 특정 주제만 거부하면 다른 주제를 제안하며, 활동 종료로 보지 않는다.
> - 무응답·휴식 요청은 아이의 종료 의도(아동 중단)로 기록하지 않는다.
> - 연결 장애·기술적 일시 정지로 답을 확인할 수 없는 시간은 무응답으로 세지 않는다.
> - 대답은 판정 모델(J1)로 판정하며, 판독 불가·불명확만으로 거부로 보지 않는다.

### FR-E04 다시 듣기·속도 조절·설명 요청

`Should` · 주체: 아이 기기 · 화면: 12 활동 진행

- **트리거:** 아이가 다시 듣기·속도 조절·설명을 요청
- **선행 조건:** 진행 중
- **입력:**
  - 요청 발화
  - 실제로 제공한 내용
- **처리:**
  1. 요청 문구가 아니라 실제로 제공한 내용으로 구분한다
  2. 같은 내용 다시 말하기·속도 조절 → 도움 아님
  3. 목표 행동의 판단 단서를 더한 설명 → 도움 제공으로 기록하고 도움 동의 원칙(FR-E08) 적용
- **출력:**
  - 무중 음성 응답
  - 단서를 더했으면 ⇒ DATA-20 제공한 도움
- **예외·분기:**
  - 첫 반응 전 → FR-E07(반복·속도 조절만)
- **하지 않는 것:**
  - 단서 없는 반복을 도움으로 집계
- **완료 기준 (기능명세서 검증):**
  - PRAC-RESP-001: 첫 반응 전 도움·정답·표현 예시 출력이 차단된다. 기회 문장은 세션 고정 대본 그대로 출력된다. J2 판정마다 정해진 다음 행동만 대화 역할에 지시된다
  - PRAC-ASK-001: 일부 전달 사례에서 되묻기가 1회만 나오고 해결되면 집중 연습 없이 이어진다. 상황 이해 못함 사례에서 표현 교정 없이 설명만 바뀐다. 기록에 되묻기·상황 재설명이 남는다
  - PRAC-CUE-001: 첫 반응 전에는 표현 예시가 나오지 않는다. 도움 요청 때는 동의 질문 없이, 그 밖에는 수락 뒤에만 집중 연습이 시작된다. 기록에 제공한 도움과 동의 응답이 남는다. 지시에 판정 라벨·기준이 없다
  - VOICE-ACCESS-001: 같은 내용 반복을 도움으로 집계하지 않고, 단서·표현 예시가 더해진 설명을 도움 없음으로 기록하지 않는다
- **상세 기능:** PRAC-RESP-001, PRAC-ASK-001, PRAC-CUE-001, VOICE-ACCESS-001
- **넘긴 결정·참고:**
  - 참고: 첫 반응 전 처리는 FR-E07

**원문**

> - 같은 내용 다시 말하기·속도 조절과, 목표 행동의 판단 단서를 더하는 설명을 구분한다.
> - 단서를 더하지 않은 반복·속도 조절은 도움(Cue)으로 집계하지 않는다.
> - 목표 행동의 단서를 더해 설명했다면 도움 제공으로 기록하고, 도움 동의 원칙(FR-E08)을 적용한다.
> - 요청 문구가 아니라 실제로 제공한 내용으로 구분한다.

### FR-E05 아동 종료 의도 인식

`Must` · 주체: 아이 기기 · 화면: 12 활동 진행

- **트리거:** 진행 중 아이 발화
- **선행 조건:** DATA-06 이번 활동에 적용된 종료 표현
- **입력:**
  - 아이 발화 전사
  - 대화 맥락
- **처리:**

- **상세 기능:** STOP-SET01-003, VOICE-STOP-001

**원문**

### FR-E08 되묻기·집중 연습과 복귀

`Must` · 주체: 아이 기기 · 화면: 12 활동 진행

- **트리거:** J2 결과 '일부 전달' / '도움 요청·지원 필요'
- **선행 조건:** 장면 진행 중
- **입력:**
  - J3 되묻기 뒤 반응
  - J4 도움 동의 응답
  - J5 다시 해 보기 반응
- **처리:**
  1. 일부 전달 → 무중이 상대 역할 그대로 1회 자연스럽게 되묻고 반응을 판정(J3). 해결되면 별도 연습 없이 이어 감
  2. 도움 요청·되묻기 뒤에도 지원 필요 → 코치 역할로 바꿔("잠깐, 무중이 도와줄게") 목표 관련 부분 하나만 짧게 집중 연습. 필요하면 표현 예시 가능, 내용은 대화 중 실시간 생성
  3. 아이가 청하지 않은 도움 → 먼저 제안하고 동의 확인(J4)
  4. 다시 해 보기 판정(J5) 뒤 "다시 친구 역할로 돌아갈게"처럼 알리고 원래 장면으로 돌아가거나 정리
- **출력:**
  - ⇒ DATA-20 장면 결과('되묻기 뒤 전달' 등)와 제공한 도움(종류·내용·동의 응답)
- **예외·분기:**
  - 도움 거절 → 집중 연습 없이 원래 장면을 이어 가거나 정리
- **하지 않는 것:**
  - 동의 없이 도움 제공
- **완료 기준 (기능명세서 검증):**
  - PRAC-ASK-001: 일부 전달 사례에서 되묻기가 1회만 나오고 해결되면 집중 연습 없이 이어진다. 상황 이해 못함 사례에서 표현 교정 없이 설명만 바뀐다. 기록에 되묻기·상황 재설명이 남는다
  - PRAC-CUE-001: 첫 반응 전에는 표현 예시가 나오지 않는다. 도움 요청 때는 동의 질문 없이, 그 밖에는 수락 뒤에만 집중 연습이 시작된다. 기록에 제공한 도움과 동의 응답이 남는다. 지시에 판정 라벨·기준이 없다
  - PRAC-RESP-002: '코치 표현 그대로 따라 함'이 '충분히 전달'과 구분돼 기록된다. 첫 반응 기록이 바뀌지 않는다
  - VOICE-ROLE-001: 코치 역할 전환·복귀 지시에 판정 기준·라벨·확률이 없다(역할 지식 누출 시험). 복귀 알림 뒤 원래 장면으로 돌아간다
- **상세 기능:** PRAC-ASK-001, PRAC-CUE-001, PRAC-RESP-002, VOICE-ROLE-001, SYS-WAIT-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 집중 연습 길이·횟수

**원문**

> - 일부만 전달됐으면 무중이 상대 역할 그대로 1회 자연스럽게 되묻고, 그 뒤 반응을 판정한다(J3).
>   - 되묻기로 해결되면 별도 연습 없이 이어 가고 ‘되묻기 뒤 전달’로 기록한다.
> - 아이가 도움을 청하거나 되묻기 뒤에도 지원이 필요하면, 코치 역할로 바꿔(예: “잠깐, 무중이 도와줄게”) 목표 관련 부분 하나만 짧게 집중 연습한다.
> - 아이가 청하지 않은 도움은 먼저 제안하고 동의를 확인하며(J4), 거절하면 집중 연습 없이 원래 장면을 이어 가거나 정리한다.
> - 집중 연습에서는 필요하면 표현 예시를 줄 수 있고, 내용은 대화 중에 상황에 맞게 실시간으로 만든다.
> - 다시 해 보기를 판정한 뒤(J5) “다시 친구 역할로 돌아갈게”처럼 알리고, 원래 장면으로 돌아가거나 정리한다.
> - 제공한 도움의 종류·내용·동의 응답을 기록한다.

### FR-E09 변형 장면 제시

>   - 생략해도 미실시 실패로 기록하지 않는다.
> - 한 목표가 10분(임시값)에 이르면 변형 장면을 더 하지 않고 그 목표의 장면을 정리한다.

### FR-E11 연결 대상별 장애 대응·복구

`Must` · 주체: 아이 기기 · 화면: 12 활동 진행, P2 예상치 못한 종료 팝업, 17 활동 끝

- **트리거:** 기기 연결·음성 모델 연결 장애 확인(아동 서비스)
- **선행 조건:** 진행 중 활동
- **입력:**
  - DATA-05 연결 관측
  - 종료 요청 여부
  - 상태·대화 맥락 복원 가능 여부
- **처리:**
  1. 음성 대화 장애가 확인되면 기술적 일시 정지 후 복구를 시도한다. 기존·지연 응답 전달과 새 대화 음성 전송을 멈춘다
  2. 기기 연결이 끊기면 아이 기기는 받아 둔 응답 재생을 스스로 멈춘다
  3. 종료 전이고 종료 요청이 없으며 상태·맥락을 정상 복원할 수 있을 때만 다시 이어 간다
- **출력:**
  - 복구 성공 → 이어 감(끊기기 전 응답은 다시 재생하지 않음)
  - 복구 실패 → 아동 서비스가 기술 문제로 종료 확인 → 종료 사실·확보 기록 범위를 보호자 서버에 전달(기기 연결이 끊겨도 확정 가능) → P2 → 17
- **예외·분기:**
  - 보호자 앱 연결만 문제 → 대화·기록을 끝내지 않음
  - 보호자 서버가 상태를 받지 못함('응답 없음')만으로 → 중단·종료로 보지 않음
  - 불명확한 말·침묵·마이크 문제·AI 지연 → 연결 장애로 판정하지 않음
- **하지 않는 것:**
  - 복구 뒤 끊기기 전 응답 재생
  - 종료 요청이 있는 활동을 복구로 재개
- **완료 기준 (기능명세서 검증):**
  - ACT-P2-001: 기술 문제 종료만 P2를 거치고 아동 중단·공백 자동 종료는 P2 없이 17·23으로 간다. 같은 세션의 27 종료 사유와 푸시 알림이 일치한다. 장애·미확인을 아동 종료 의도나 실패로 추정하지 않고, 보호자 서버의 기록 미수신을 아동 거부나 대화 없음으로 바꾸지 않는다
  - DEV-CLIENT-001: 기기 연결을 끊으면 재생이 멈추고 재연결 후 이전 응답이 재생되지 않는다. 보호자 앱의 기능·화면은 기기 형태와 무관하다
  - VOICE-ERR-001: 네 가지 장애를 각각 주입하면 공통규칙 AC-CON-01~10대로 표시·처리된다(12·21은 '잠깐 끊김', 04·05는 대상별 표시, T19는 '연결 끊김·다시 연결 중', 기술 종료는 P2)
- **상세 기능:** ACT-P2-001, DEV-CLIENT-001, VOICE-ERR-001, VOICE-NOTICE-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 장애 판정 시간, 복구 대기시간, 재시도 횟수, 재개 판정 조건
  - 결정 필요: 아이에게 들려줄 고정 안내의 제공 여부·문구·횟수(기술적으로는 가능)

**원문**

> - 보호자 앱 연결만 문제면 기기의 대화·기록을 끝내지 않는다.
> - 기기 연결·음성 모델 연결 장애(음성 대화 장애)는 아동 서비스가 직접 확인하고, 확인되면 기술적 일시 정지 후 복구를 시도한다.
>   - 이때 기존·지연 응답 전달과 새 대화 음성 전송을 멈춘다.

### FR-F01 세션 상태 관리

  - 보호자 앱 접속 여부를 활동 상태로 쓰기

  - NOTI-PUSH-002: 복구 후 과거 장애 알림을 선택하면 최신 상태로 이동한다

> - 다시 시도해도 같은 활동의 결과는 한 번만 만들어지고, 원래 대화·연습 기록은 지우거나 바꾸지 않는다.

### FR-F18 대화 진행·연결 관측 상태 판정

`Must` · 주체: 서버 · 화면: 12 활동 진행, P2 예상치 못한 종료 팝업

- **트리거:** 진행 중 연결 관측 · 오디오 공백
- **선행 조건:** 진행 중 활동
- **입력:**
  - 연결 대상별 관측과 마지막 확인 시각(DATA-05)
  - 아동 서비스가 받은 음성
  - 휴식 요청 기록(DATA-13)
- **처리:**
  1. 활동 진행 사실과 연결 관측 사실을 구분해 진행 화면 대화 흐름에 반영한다
  2. 음성 대화 장애·보호자 서버 상태 미수신·보호자 앱 조회 불가·아이 침묵·마이크 문제·AI 응답 지연을 근거에 따라 구분한다
  3. 연결이 정상이고 공백을 직접 확인할 수 있을 때만, 실제 오디오 공백이 4분이면 비정상 공백으로 보고 추가 약 2분(기본 2분) 뒤 자동 종료한다
- **출력:**
  - 자동 종료 → 종료 처리 중 → 기기 종료 확인 뒤 17(팝업 없음)·완료 알림
  - ⇒ DATA-22 종료 사유 '대화 거부'(휴식 요청 없음) / '비정상 오디오 공백 지속'(휴식 요청 뒤)
- **예외·분기:**
  - 근거가 없음 → 원인을 추정하지 않음
  - 유효시간이 지남 → 마지막 상태를 현재 정상으로 보여 주지 않음
  - 장애·상태 미확인·기술적 일시 정지 시간 → 공백에 더하지 않음. 연속성이 확인되지 않은 구간을 이어 붙여 종료하지 않음
  - 보호자 서버·앱의 수신 공백 → 대화 공백으로 세지 않음
- **하지 않는 것:**
  - 4분 공백을 진행 화면에 표시
- **완료 기준 (기능명세서 검증):**
  - DEV-S05-001: 기기 연결 장애·음성 모델 연결 장애·부모 앱 연결 장애·상태 미수신을 각각 주입하면 대상과 확인 수준이 구분돼 표시된다. 부모 앱만 오프라인이면 활동·기록은 지속되고 앱에 마지막 확인 시각·상태가 보인다. 등록 전에는 기기 등록 줄이 '없음'이고 「+ 기기 등록」이 보인다(04는 '연결된 기기 없음')
  - ACT-S12-001: 대화 중 무중·아이 발화가 시각과 함께 순서대로 보인다. 음성 대화 장애를 주입하면 '잠깐 끊김' 구간 하나가 생기고, 앱만 오프라인이던 동안 계속된 대화는 재조회 후 실제 전사로 이어진다. 상태 미수신 구간은 재전달 후 실제 기록으로 바뀐다. 종료 확인 후에만 17(기술 문제 종료는 P2 안내 후)로 바뀐다
  - PRAC-S21-001: 상단에 시작 시각·n분째만 있고 단계·목표 번호가 없다. 연습 대화가 시각과 함께 순서대로 보인다. 음성 대화 장애와 상태 미수신 구간이 모두 '잠깐 끊김'으로 표시되고 기록에서는 구분된다. 기술 종료 확인 후 P2 → 23으로 연결되며 장면 미실시를 실패로 처리하지 않는다
  - SYS-OBS-001: 마이크 문제·AI 지연·침묵이 연결 장애로 일괄 표시되지 않는다. 재연결 기록 일부만 받으면 남은 구간은 미확인이다
  - SYS-GAP-001: 정상 연결의 확인 가능한 연속 공백만 4분·추가 2분에 반응한다. 휴식 요청 유무에 따라 종료 사유가 갈린다. 앱만 오프라인·상태 미수신·장애 시간으로 자동 종료되지 않는다
- **상세 기능:** DEV-S05-001, ACT-S12-001, PRAC-S21-001, SYS-OBS-001, SYS-GAP-001
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 상태 정보 유효시간, 장애·복구 시간(4분+2분과 별도 기준)
  - 결정 필요: 정상 대화 복원 시 공백 누적 초기화, 미확인 구간 전후 타이머 전환

**원문**

> - 활동 진행 사실과 연결 관측 사실을 구분해 진행 화면의 대화 흐름에 반영한다.
> - 음성 대화 장애, 보호자 서버 상태 미수신, 보호자 앱 조회 불가, 아이 침묵, 마이크 문제, AI 응답 지연을 근거에 따라 구분하고, 근거가 없으면 원인을 추정하지 않는다.
> - 연결 대상별 마지막 확인 시각을 관리하고, 유효시간이 지나면 마지막 상태를 현재 정상으로 보여 주지 않는다.
> - 연결이 정상이고 공백을 직접 확인할 수 있는 활동 중에만, 실제 오디오 공백이 4분이면 비정상 공백으로 보고 추가 약 2분(기본 2분) 뒤 자동 종료한다.
>   - 4분 공백은 내부에서만 판정하고 진행 화면에 따로 표시하지 않는다.
> - 장애·상태 미확인·기술적 일시 정지 시간은 공백에 더하지 않고, 연속성이 확인되지 않은 구간을 이어 붙여 종료하지 않는다.
>   - 보호자 서버·앱의 수신 공백을 대화 공백으로 대신 세지 않는다(공백은 아동 서비스가 받은 음성 기준).
> - 자동 종료 사유: 공백 전에 휴식 요청이 없었으면 ‘대화 거부’, 휴식 요청 뒤 이어진 공백이면 ‘비정상 오디오 공백 지속’
> - 기기 자동 종료가 확인된 뒤에만 완료 알림과 종료 화면(P2 없이)을 보여 준다.

### FR-F19 연습 목표 관리

`Must` · 주체: 서버 · 화면: 18 내 연습 목표, 27 활동 기록 상세

  3. 연습 뒤 연습 횟수와 지난 장면 기록을 갱신한다

- **하지 않는 것:**
  - 미리 넣어 둔 기본·예시 목표
  - 권장 연령
  - 담을 수 있지만 연습부터 결과까지 동작하지 않는 목표
- **완료 기준 (기능명세서 검증):**
  - PRAC-S18-001: 27에서 담은 목표만 나오고 담은 곳·연습 횟수가 표시된다
  - PRAC-S18-003: 즐겨찾기 지정·해제와 삭제(확인 후)가 저장되고 기록은 그대로다
  - HIST-S27-005: 후보마다 실제 근거 기록이 연결되고, 담은 후보만 18에 나온다
  - SYS-GOAL-001: 담을 수 있는 모든 목표가 상황 생성부터 결과 생성까지 동작한다. 담기·즐겨찾기·삭제가 저장되고 연습 뒤 연습 횟수·지난 연습 기록이 갱신된다. 목표에 연령 정보가 없다
- **상세 기능:** PRAC-S18-001, PRAC-S18-003, HIST-S27-005, SYS-GOAL-001

**원문**

> - 기록에서 만든 아이별 목표 후보와 보호자가 담은 목표(즐겨찾기·담은 순서·연습 횟수·지난 장면 기록)를 관리한다.
> - 각 목표에는 이름·설명과 4요소(핵심 기능 정의, 연습 기회 조건, 상황 생성 조건, 반응 판정 기준)를 담고, 4요소는 분석 AI가 작성한다.
> - 4요소를 갖추지 못한 목표는 후보로 보여 주지 않고, 갖춘 목표는 사람의 별도 검토 없이 보호자에게 보여 준다.
> - 미리 넣어 둔 기본·예시 목표와 권장 연령은 두지 않는다.
> - 담기·즐겨찾기·삭제는 저장되고, 연습 뒤 연습 횟수와 지난 장면 기록이 갱신된다.
> - 담을 수 있는 모든 목표는 상황 만들기부터 반응 기록·결과 생성까지 동작한다.

### FR-F20 진행 중 반응 판정 (판정 모델)

`Must` · 주체: 서버 · 화면: 12 활동 진행

- **트리거:** 판정 차례(기회 문장 직후 등 J1~J7)
- **선행 조건:** 진행 중 활동
- **입력:**
  - 아이 발화 전사
  - 판정 질문·선택지·판정 기준·장면·최근 몇 턴(NFR-04)
- **처리:**
  1. 판정 차례에는 GPT Live의 자동 응답을 잠시 멈추고 아이 발화 전사를 제브에 보낸다
  2. 제브는 텍스트만 받아 정해진 선택지 중 하나를 확률과 함께 돌려준다
  3. 판정 결과로 다음 행동을 정해 GPT Live에는 '다음 행동 지시'만 준다. 일반 대화 차례는 자동 응답을 그대로 쓴다
  4. 판정 지점: J1 시작 안내 응답, J2 기회 직후 반응, J3 되묻기 뒤 반응, J4 도움 동의, J5 집중 연습 뒤 재시도, J6 종료 의도, J7 생성 대본 사전 점검
- **출력:**
  - 다음 행동 지시 → GPT Live
  - ⇒ DATA-14 진행용 판정(지점·선택지·1·2순위 확률·보류 여부·소요 시간) → 활동 뒤 기록용 재판정으로 확정
- **예외·분기:**
  - 1순위 확률이 낮거나 1·2순위 차이가 작음 → 판정 보류, 교정 없이 되묻기(판독 불가는 다시 말해 달라는 확인)
  - 전사가 제한 시간 안에 오지 않음 → 판독 불가
  - 제브 응답이 늦음 → 판정 보류, 무난한 되묻기 지시
  - 아이 말이 끝나고 10초(임시값) 안에 응답 준비 안 됨 → 판정 보류, 되묻기나 맞장구
- **하지 않는 것:**
  - GPT Live가 직접 판정
- **완료 기준 (기능명세서 검증):**
  - PRAC-RESP-001: 첫 반응 전 도움·정답·표현 예시 출력이 차단된다. 기회 문장은 세션 고정 대본 그대로 출력된다. J2 판정마다 정해진 다음 행동만 대화 역할에 지시된다
  - PRAC-ASK-001: 일부 전달 사례에서 되묻기가 1회만 나오고 해결되면 집중 연습 없이 이어진다. 상황 이해 못함 사례에서 표현 교정 없이 설명만 바뀐다. 기록에 되묻기·상황 재설명이 남는다
  - PRAC-CUE-001: 첫 반응 전에는 표현 예시가 나오지 않는다. 도움 요청 때는 동의 질문 없이, 그 밖에는 수락 뒤에만 집중 연습이 시작된다. 기록에 제공한 도움과 동의 응답이 남는다. 지시에 판정 라벨·기준이 없다
  - PRAC-RESP-002: '코치 표현 그대로 따라 함'이 '충분히 전달'과 구분돼 기록된다. 첫 반응 기록이 바뀌지 않는다
  - VOICE-START-001: AI 정체와 종료 방법을 안내하고 참여 의사를 처리한다. 추가 종료 표현은 다음 활동부터 반영된다. 휴식 요청이 거부로 처리되지 않는다
  - VOICE-STOP-001: 키워드는 확인 질문 없이 종료된다. 키워드가 아닌 명확한 종료 의도도 처리된다. 대사·재생 음성·주제 거부·휴식 요청으로 종료되지 않는다. 종료 확정 후 이전 응답이 재생되지 않는다
  - VOICE-ROLE-001: 코치 역할 전환·복귀 지시에 판정 기준·라벨·확률이 없다(역할 지식 누출 시험). 복귀 알림 뒤 원래 장면으로 돌아간다
  - SYS-PRAC-001: 세션에 쓰인 모든 기회 문장이 자동 확인과 J7 통과 기록을 가진다. 정답 문장이 든 대본은 쓰이지 않는다
  - SYS-EVAL-001: 같은 기회의 집중 연습 뒤 반응을 독립 성공으로 바꾸지 않는다. 판정 기준이 없는 목표는 연습 대상이 아니다. 27 장면 결과가 기록용 재판정과 일치한다
  - SYS-ROLE-001: 역할 지식 누출 시험이 통과하고, GPT Live 요청에 판정 라벨·확률·기준이 없으며, 공급자 요청 로그에 목적 밖 필드가 없다
  - SYS-JUDGE-001: 판정 턴에서 GPT Live가 지시 전에 스스로 응답하지 않는다. GPT Live 요청 로그에 판정 라벨·기준이 없다. 판정 결과마다 정해진 다음 행동이 지시된다
  - SYS-JUDGE-002: 모든 판정 지점이 정한 선택지 중 하나 또는 보류만 낸다. 문턱 미달 사례에서 교정·집중 연습이 나오지 않는다
  - SYS-JUDGE-003: 전사 지연·제브 지연을 각각 주입하면 판독 불가 확인·무난한 되묻기로 이어지고 교정이 나오지 않는다. 전사·판정이 모두 늦어도 아이 말이 끝난 뒤 10초 안에 되묻기나 맞장구가 나온다. 늦게 온 판정이 다음 행동을 바꾸지 않는다
  - SYS-JUDGE-004: 판정마다 기록이 한 건씩 남고 27 확정 값과 구분된다. 아동·계정 삭제 때 함께 지워진다
- **상세 기능:** PRAC-RESP-001, PRAC-ASK-001, PRAC-CUE-001, PRAC-RESP-002, VOICE-START-001, VOICE-STOP-001, VOICE-ROLE-001, SYS-WAIT-001, SYS-PRAC-001, SYS-EVAL-001, SYS-ROLE-001, SYS-JUDGE-001, SYS-JUDGE-002, SYS-JUDGE-003, SYS-JUDGE-004
- **넘긴 결정·참고:**
  - ADR로 넘긴 값: 전사 대기·제브 응답 제한 시간(10초 안), 판정 턴 맞장구 문구 여부, 아이 기기 에코 제거
  - 검증 과제: 제브 한국어 아동 발화 정확도, 확신 문턱값
  - 참고: 응답 공백 허용 10초는 임시값 / 판정 지점별 선택지는 명세서 FR-F20 상세 참조

**원문**

> - 진행 중 아이 반응 판정은 판정 모델 제브(Jev)가 맡는다. 제브는 텍스트만 받아 정해진 선택지 중 하나를 확률(신뢰도)과 함께 돌려준다.
> - 역할 나눔: GPT Live는 실시간 음성 대화·실시간 도움·아이 발화 전사, 제브는 진행 중 판정, 분석 AI는 활동 전·후 처리(목표 후보·대본·기록용 재판정·결과 문장·생활 팁·리포트)를 맡는다.
> - 판정할 차례(기회 문장 직후 등)에는 GPT Live의 자동 응답을 잠시 멈추고, 아이 발화 전사를 제브에 보내 판정한다.
>   - 판정 결과로 다음 행동을 정해 GPT Live에는 ‘다음 행동 지시’만 주고, 일반 대화 차례는 자동 응답을 그대로 쓴다.
> - 판정 지점: J1 시작 안내 응답, J2 기회 직후 반응, J3 되묻기 뒤 반응, J4 도움 동의, J5 집중 연습 뒤 재시도, J6 종료 의도, J7 생성 대본 사전 점검
> - 1순위 확률이 낮거나 1·2순위 차이가 작으면 판정 보류로 두고 교정 없이 되묻는다(판독 불가는 다시 말해 달라는 확인).
> - 전사가 제한 시간 안에 오지 않으면 판독 불가로, 제브 응답이 늦으면 판정 보류로 처리하고 무난한 되묻기를 지시한다.
>   - 응답 공백 허용 10초(임시값): 아이 말이 끝나고 10초 안에 응답이 준비되지 않으면 판정 보류로 두고 되묻기나 맞장구로 응답한다.
> - 판정 차례마다 판정 지점·선택지·1·2순위 확률·보류 여부·소요 시간을 진행 기록으로 남기고, 기록은 활동 뒤 기록용 재판정으로 확정한다.
